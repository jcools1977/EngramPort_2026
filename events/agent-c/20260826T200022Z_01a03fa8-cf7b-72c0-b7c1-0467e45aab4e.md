## Findings

- Mandatory completeness check cannot be done from current evidence. The dispatch requires checking agent-b's answer about what the old broad ban covered that the four enforcement properties do not, but that answer is not in the target event or any supplied file. Thread-config digest specimens are also absent. Those are remaining prerequisites, not optional color.
- The dispatch repeats the last-round verification failure mode. It asserts the unmatched-path defect is genuinely fixed (tracked secrets/creds.env => unaccounted=1) and orders agent-c not to re-derive that claim, while also saying agent-a's verification is what failed last round. No proof:verify output or failing-test transcript is in the evidence. A critic cannot accept an execution claim that is both un evidenced and fenced off.
- Agent-a's HEAD reading is not wrong; it is too generous. loadProtectedActors compares worktree yaml names and bytes to HEAD. On the clean checkouts and CI runs that multi-builder collaboration actually uses, worktree equals HEAD, so the comparison is tautological. A second builder's committed actors/ edit becomes the new baseline and then passes. The only time this fires is a local dirty tree, which is not the ADR 0039 threat.
- The protected-surface claim is broader than the control. Only actors/*.yaml basename set and yaml bytes are compared to HEAD. Tracked non-yaml under actors/ is classified protected by path prefix in the surface test and is never content-compared to HEAD, so it does not fail loadProtectedActors. Registry protection is yaml-file hygiene, not actors/ tree integrity.
- disjoint prefixes does not survive the path tricks the dispatch named. inSurface/assertDisjoint are case-sensitive JavaScript string-prefix checks with no realpath, Unicode normalization, or symlink resolution. Filename is not bound to slug; agent-b.yaml may declare slug Agent-B. Two actors can therefore pass as disjoint while case-folding or symlink-aliasing to the same events/ or artifacts/ directory on a case-insensitive filesystem. That is the F103 gap reintroduced. Trailing slashes on a single-sided prefix are mostly caught; case and symlink identity are not.
- In-repo digest binding fails the same committed-edit way as HEAD comparison if the expected digest lives in the tree: the attacker updates subject and binding together. Stronger than agent-b's already-stated disable-the-control limit: the enforcement test and the AGENTS.md rule strings sit on shared-editable surfaces (tests/, AGENTS.md), while actors/*.yaml is the thing called protected. One commit can rewrite the registry, the test, and the policy text. No in-repository mechanism here establishes registry integrity against ADR 0039; that requires write-gating or owner binding outside the mutable tree. Shipping this as protection would oversell a dirty-tree check.
