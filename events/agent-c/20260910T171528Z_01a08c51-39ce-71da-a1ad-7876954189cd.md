The proposed agent-b implementation dispatch is completable on the named shared write paths. Observation routing (appendEvent in a temporary scaffold, inbox only for inbox properties, report output for derived state, mutations that must start accepting what they should refuse) avoids the ADR 0052 first-draft faults: there is no global pre-fix clause, and inbox is not used as a witness for non-inbox properties. v1 remains appendable and the live log must stay v1-only until later acceptance. Residual holes do not make the work unsatisfiable, but several mandatory ADR properties are not discriminating in the bound criteria, and the writer-cutover sentence never accounts for correction as v2-only vocabulary.

## Findings

- environment-required does not discriminate the objective/ADR environment shape. It observes omission, malformed observed_at, a generic explicit-unknown accept, and v1-without-environment. It does not observe the four named members, structured version (source_revision, dirty, runtime, subject), unknown on each member, or refusal of a fifth member. A looser object with an observed_at would satisfy the criterion.
- contested-derived omits two mandatory clearing/distinctness rules from objective item 3: owner re-statement of the criterion naming the assumed environment, and that Re:PORTer “cannot tell” stays distinct from contested. Named tests cannot kill an implementation that never clears on owner restatement or that aliases the two states.
- Correction adds type correction and field corrects, which cannot validate against an untouched v1 schema (closed types / additional properties). The writer-cutover sentence only says the writer emits v2 for completions that carry environments and still accepts v1 for everything else. It never states that correction must be a v2 writer event, so that sentence and items 1, 4, and the v1-untouched bound are under-specified together rather than jointly closed.
- Live retry/idempotence in event-core.mjs matches only schema_version === 1, and hashAppendIntent’s canonical fields do not include corrects (or schema_version). The dispatch names those symbols as read paths but does not require extending them, and no criterion observes v2 retry reuse versus intent collision when corrects differs. A v2 writer plus correction can miss the existing retry contract while still passing the bound criteria.
