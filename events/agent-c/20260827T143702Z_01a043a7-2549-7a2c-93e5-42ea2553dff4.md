# Agent-c result review

Result verdict: **rejected**  
Unique finding produced: **true**  
Finding disposition: **pending**

The delivered Port Watch package does not make the assessed conjunct true. decideDelivery is a local project_seq watermark filter, not delivery; decideWatch then drops everything except one handoff with implementation_authority===true. Cursors live in an in-process-serialized JSON file, so they survive a same-machine restart and nothing ADR 0039 treats as the product (clone, second machine, second builder, git substrate). tick decides and may invoke an injected runner; it does not deliver work into the log or inbox. listInbox still full-scans on next/unanswered, so the two surfaces can disagree about what is new. Claim fails; not a missing-test conditional.

## Findings

- decideDelivery does not deliver. It filters events with project_seq>cursor, sorts them, and returns wake|skip. Calling that delivery oversells a watermark selector. The site sentence needs a behavior that hands new work to a builder's agent; this function never does.
- decideWatch is narrower still: after the watermark it keeps only the first kind===handoff with implementation_authority===true, else skip/no_eligible_handoff. Replies, artifacts, completions, and ordinary new events are not delivered. The conjunct says new work, not a single authorized handoff.
- Cursors are not durable in the product sense. FileWatchStore is a local JSON file with atomic rename and an in-process pending chain. That is restart-durable on one filesystem. ADR 0039 defines the product as multiple builders on their own machines with git as substrate. This cursor is not an event, not cloned, not shared, and a fresh clone starts at cursor 0.
- tick does not deliver; it decides, then calls runner.run(context, token) if wake. RecordingRunner only records. Nothing is appended, addressed, or made discoverable. The Discover copy promises a user-visible delivery path; this is an optional supervisor callback.
- Port Watch and listInbox cannot agree on what is new. listInbox full-scans the log for meta.next===actor and unanswered in_reply_to. Port Watch uses a numeric project_seq cursor, then the handoff/authority gate. complete() sets cursor=max(cursor, run.project_seq), which can hide intervening events from the watch while leaving them unanswered in the inbox, and the reverse: an eligible handoff can wake the watch while never appearing in listInbox.
- Resume without re-reading the log is not established (ADR 0040's reason for the claim). tick always calls inbox.queryAuthorized; this package does not read the log incrementally. The cursor is applied to an events array the inbox already produced. If that inbox is listInbox-shaped, the watermark does no I/O work the claim advertises.
- The inbox contract is a second drift surface inside the package. tick queries {after:snapshot.cursor} then decideDelivery re-filters project_seq>cursor. after is unspecified here. If the authorized query does not mean project_seq, the fetch and the decision disagree by construction.
- FileWatchStore and key(agent,project) assume a single writer. pending serializes only inside one process. Two processes can both read, both set active_run, and last-rename wins, so two runners can run. Under ADR 0039 that is the multi-builder case, not an edge. A shared file is a race; per-machine files are divergent cursors for the same agent:project.
- WIP/lease state contradicts continuous delivery. An active_run makes every later tick skip/wip_limit. stop() revokes the lease but leaves active_run set, so complete() throws LEASE_NOT_ACTIVE and ticks keep skipping until expireLease. expireLease clears the run without advancing the cursor. Delivery can stall forever on one slot, or re-wake the same handoff after expiry, neither of which is cursor-driven delivery of new work.
- rewind allows a non-operator caller to advance the cursor forward with no audit event, silently skipping seqs. Only backward movement is refused without operator. A durable cursor that any caller can jump forward is not a trustworthy resume point.
