# Handoff: build work deliveries only, and treat observations as unresolved

**Agent-c stopped the full dispatch and found a hole in council 03's decision rather than in agent-a's wording.** Recorded as F121 and F122. Both voters sealed independently and converged on deriving position from the log, and **the design is unsatisfiable for one of its two delivery classes.**

**Only the buildable half is dispatched.** Agent-c's assessment is that work-only, log-derived eligibility is implementable; the conjunction is not.

## Build

**Work deliveries, position derived from the log, never stored.** Addressed, unanswered, authorized. **The reply is the disposition**, which is why this half works: `next` plus an answering `in_reply_to` fully determines the set.

**One eligibility resolver shared with `listInbox`**, not a second implementation. Agent-c notes `decideWatch` consumes a different model (`kind`, `project_seq`, `implementation_authority`, `event_id`) that git events do not carry, so **say whether a shared type can be extracted at all**, and if it cannot, that is a finding rather than a thing to force.

**A disposable cache keyed to log state.** Deleting it costs time, never correctness.

**Solve the duplicate-wake hazard explicitly.** Removing stored position removes `FileWatchStore`'s single-writer lock, so two ticks can both invoke the runner for the same work. **This is the defect agent-a's proposed test could not have caught**, since two pure reads of one log cannot disagree about a set. **The control must observe a duplicate invocation, not a set mismatch.**

## Not in scope, and why

**Observation deliveries are withdrawn pending a protocol decision.** There is nowhere to record that an observation was delivered: a reply cannot dispose of one, there is no stored cursor, and a cache may not change the set. Undisposed, they stay eligible forever and every clone re-offers the whole thread history.

**Do not work around this.** The resolution is a protocol question for the council and DeVere: either a delivery-disposition event type, or an explicitly accepted stored projection with defined rebuild semantics. **Agent-a will raise it; do not decide it inside this slice.**

Also out of scope: any subscription authorization model. Thread membership is a leak path, not authorization, and `threads/*.yaml` as a roster is enrollment.

## Evidence

Discriminating mutation per property. A fresh clone reproduces the identical work-delivery set, which is the F115 defect that began this. Cache deletion changes timing and not the set, **with a deterministic probe rather than a wall-clock assertion**. Duplicate invocation is observed and prevented. **Existing local lease and cursor state has no log equivalent: say what happens to in-flight work rather than discarding it silently**, since discarding can double-run it.

**Bounds.** Port Watch and the shared resolver. No SDK, no new event type, no envelope change, no enrollment, no observation class. **`executed=` moves from its observed value, which you state**, since agent-a asserting 129 was outside these bounds and agent-a has miscounted it before.
