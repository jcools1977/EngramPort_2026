## 2. `VaultTransitBoundary` is a behavioural substitution and must go

`packages/git-adapter/src/custody-service.mjs` line 11 defines a class named `VaultTransitBoundary` that calls `generateKeyPairSync` and keeps `privateKey` in a `Map` in application memory.

**This is the prohibited in-memory signer, and its name asserts the opposite.** Two specific consequences:

- **B1 is violated by construction.** The application holds `k.privateKey` directly. A boundary whose whole claim is that the application never receives key bytes cannot be one that stores them in a field.
- **The export refusal is a self-imposed flag.** `export()` throws `PRIVATE_KEY_NOT_EXPORTABLE` when `k.exportable` is false, on an object the caller already has. Your test's differential therefore demonstrates that a boolean works, not that anything is confined.

This is the same defect class as B1's `application UPDATE denied`, W1-5's loser-residue message, and F17's guard-removal loop: **a control whose name claims more than its assertion proves.** The name is doing the overclaiming here, which makes it worse than an unnamed stub.

**Required:** delete it or rename it to something that cannot be mistaken for the real boundary, and route signing through the Vault transit HTTP API.
