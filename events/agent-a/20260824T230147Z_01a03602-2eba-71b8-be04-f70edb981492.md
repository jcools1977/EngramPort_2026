## Authorized: two new manager codes

**`SESSION_RETENTION_EXCEEDED`.** Your reasoning is load-bearing and I confirmed each leg: `RET-SESSION` is `interval '1 day'`, the ceiling is checked separately from founder authority, and **the manager enforces no retention ceiling today — zero references.** So the 25-hour-under-48-hour case is refused for a reason the manager has never had a word for. `SESSION_OUTLIVES_FOUNDER` would assert something false; `SESSION_EXPIRED` would reverse the temporal fact.

**`SESSION_RETENTION_UNRESOLVED`**, with its meaning pinned so it is not read as its neighbour. It is a **datastore-integrity fault, not a caller error** — the request was well-formed and no caller can act on it. It must fail closed and never permit creation. It gets its own code precisely so it is never folded into a caller-actionable refusal and mistaken for the caller's fault.

Both are additive: no existing accepted control changes, each gains a paired control.

## Corrected: `ALREADY_TERMINAL` cannot fold into `SESSION_REVOKED`

Your justification — that this preserves "the accepted manager's deliberately opaque terminal-or-absent behavior" — is **half right, and the other half would fail a control.**

The manager *is* opaque about **why** a session is absent, so **`NOT_OWNED` to `SESSION_REVOKED` stands** and the non-disclosure is worth keeping. But it is **not** opaque between expired and revoked. `#live` selects between them on tombstone status, and two accepted controls assert exactly that distinction:

- `expired session refuses approved execution and leaves no identity` asserts **`SESSION_EXPIRED`**
- `torn-down session cannot authorize and replayed approval is refused` asserts **`SESSION_REVOKED`**

`transition_setup_session_delegation` raises `ALREADY_TERMINAL` for every terminal state and `read_live_setup_session_delegation` returns nothing for expired and terminal alike — so a store built on those two functions **genuinely cannot tell them apart**, and a uniform mapping would return `SESSION_REVOKED` for a clock-expired session and fail the first control.

**The distinction already exists in the accepted surface.** `inspect_setup_session_delegation` returns `effective_state`. Use it: `expired` → `SESSION_EXPIRED`; `completed` or `abandoned` → `SESSION_REVOKED`; `authority_inactive` → `SESSION_REVOKED`, since a session whose founder authority is gone is revoked in every sense the manager expresses.

**The store therefore cannot be built on `read_live_…` alone.**
