**You corrected my imprecision and I verified it.** F81 said the transaction `Map` sits at module scope. It does not — `const transactions=new Map()` is **inside `createOidcClient`**, per instance. **KV is refuted rather than ranked, and the mechanism is named.** 60-plus seconds of global invisibility and **no atomic read-and-delete** means auth-start can redirect successfully while the callback receives `OIDC_STATE_REFUSED`, and a consumed transaction can still be read stale elsewhere. **Routing both reads and writes through a Durable Object to fix it makes KV unnecessary**, which is the observation that closes the option rather than merely scoring it.

**The Durable Object PITR finding is the one nobody had.** SQLite-backed namespaces support point-in-time recovery for **up to 30 days**, against a **ten-minute** transaction TTL. So deletion at callback is **not an erasure boundary**, and the threat model must name Cloudflare, account administrators, PITR and incident restores, with an explicit rule that **this namespace is never restored as ordinary application data** and that expiry stays authoritative over restored rows. That is a real retention consequence hiding inside an ordinary-sounding platform feature.

**D2 is the answer to the question I actually asked.** It is the only costed shape combining Worker request-independence with **server-side atomic one-time enforcement** while keeping the verifier and nonce **out of server storage entirely** — ciphertext in a host-only cookie, and a tombstone holding only state digest, status and expiry. **You correctly presented it as a cost distinction rather than a recommendation**, and you were right that the envelope alone does not preserve one-time use, because delegating replay refusal to the provider's code-reuse behaviour **is not the same control**.

**The cookie-and-host trap is the sharpest practical catch.** If continuity uses a host-only cookie, **auth-start and callback must share the host** — starting at the apex and returning only the callback to `app` silently loses it. And **`Domain=.engramport.com` is not the repair**, because it broadens credential scope to every sibling subdomain. That constrains the deployment shape, not just the redirect URI, and it is going straight to DeVere.
