# ACCEPTED: criterion 3 CLOSES. You found the ordering without touching a guard

Reproduced independently: `db:test` exit 0 at **`executed=72`**, `npm test` **236 / 0 / 0 skipped**, `session:async-negative` `enumerated=t`, harness `--negative` exit 1, lint 0, proof 251, clean tree.

**The construction is the right answer to a question I half expected to come back as a reading.** The shipped order runs `approvalRevoked` before `#requireLive`, so ordinary same-manager teardown can only ever produce `APPROVAL_REPLAY_REFUSED` — which is exactly why criterion 3's revoked-execution observation did not exist. Two `PostgresSetupSessionStore` instances over one database, with independent process-local approval registries, let the durable row go terminal while the issuing store's approval stays unmarked. **That is not a contrivance; it is the ordinary multi-process topology**, which makes the observation more meaningful rather than less.

**The isolation is exact, and that is what I checked hardest.** `unreplayed` is read from `approvalRevoked` — **the same predicate the replay guard itself consults** — so the refusal provably cannot be attributed to replay. `genuine` is an object-identity comparison against the approval the store issued. `durable=completed` is the second store's real transition. The refusal is `SESSION_REVOKED` from `#requireLive`, and nothing else could have produced it.

**The mutation removes only `#requireLive(session_id,snapshot)` and leaves the replay guard intact**, so the forbidden execution succeeds precisely because liveness is gone. `applied=t` is verified by grepping the marker in the variant. **No accepted guard was reordered and no production module changed** — confirmed by diff, not by report.

## Disposition

**W1-1 criterion 3 CLOSES.** An expired session cannot execute an approved step (`SESSION_EXPIRED`), and a durably revoked session cannot execute a genuine unreplayed approval (`SESSION_REVOKED`), both named, both through the composed durable path, both mutation-defended.

**W1-1 criterion 2 also CLOSES**, recorded now rather than left in limbo. "No standing wizard principal or actor exists in any code path, proven by a test asserting no identity outlives a session" is satisfied twice over: `identityInventory` returns `wizard_principals:0, wizard_actors:0` and drops session bindings, delegations and credentials to zero after completion and after abandonment, asserted in accepted controls that now run against **both** adapters; and ADR 0020 gave `setup_session_delegations` **no actor column at all**, so it survives by construction rather than by cleanup discipline.

**W1-1 stands at four of five criteria closed** — 2, 3, 4 and 5. **Criterion 1's authentication half is the only thing left, and it is DeVere's**, not yours.

## Dispatched: the OIDC verifier against synthetic fixtures only

The half of criterion 1 that needs no authorization. Build the founder authentication verifier that `SetupSessionManager`'s injected `authenticator` interface has always stood in for, **against synthetic keys and synthetic tokens only**. No real provider, no real credential, no real tenant, nothing that reaches a network.

Required, each with a paired positive and a discriminating mutation:

1. **Signature verification** against a synthetic JWKS, including **key rotation** — a token signed by a retired key is refused, one signed by the current key is accepted.
2. **Algorithm confusion refused**: `alg: none`, and an RS256 key presented for HS256 verification. These are the two that turn a verifier into a rubber stamp, and both must fail closed.
3. **Issuer, audience, expiry and nonce** each refused independently, so no single check carries another's weight.
4. **The identity surface stays exactly `principal_id`** — the accepted control already asserts the authenticator returns identity only and never stores the credential, and that must continue to hold.

**Return a reading rather than guessing if the token-to-`principal_id` mapping is underdetermined** — that binding is a real design question and it is the kind of thing that should not be settled inside an implementation. `executed=` moves from 72 on observed execution.

This leaves W1-1 with nothing unblocked once it lands.
