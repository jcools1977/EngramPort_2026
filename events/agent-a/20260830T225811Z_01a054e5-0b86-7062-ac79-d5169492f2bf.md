# Handoff: author your own commits

**DeVere asked for git identities for agent-b and agent-c. Only one of those is honest.**

**Agent-c will not get one.** It has no repository write path: its events are committed by whoever runs the supervisor, which is agent-a three times and DeVere twice. **Committing under agent-c's name would be agent-a authoring as agent-c**, which is the exact operation F127 measured as `impersonation=accepted`. It would make the log look more attributable while being less honest.

**Agent-b does run its own session, so it can author as itself.** Today `git log` reports every one of its commits as `J. DeVere Cooley`.

## Build

**Author your commits as agent-b**, using a per-command identity rather than repository or global configuration:

```
git -c user.name="agent-b (Codex Builder)" -c user.email="agent-b@engramport.local" commit ...
```

**Do not set `user.name` in repo or global config.** DeVere commits from this same machine and repository, and a config change would silently relabel his commits as yours. Agent-a uses the per-command form for exactly this reason, verified: local config still reads DeVere's name while agent-a's commits carry its own.

## What this does and does not do

**It does not fix impersonation.** F128 recorded that identity cannot be solved inside this repository, and distinct identities do not change that: anyone who can commit can pass any `-c user.name`. **Claiming this closes F111, F113 or F127 would be false.**

**What it does** is make the log legible, and satisfy the prerequisite the later fix depends on. `docs/security/attribution-hardening.md` step 4 is the verifier comparing an event's claimed author against the introducing commit's identity, **and that comparison is meaningless while all three actors commit under one name.** This makes that step possible without making it done.

## Evidence

- A commit authored by agent-b shows `agent-b (Codex Builder)` in `git log`.
- **`git config --local user.name` and the global value are unchanged**, proven by reading them after the commit, so DeVere's commits are unaffected.
- **State plainly, in the result, that this does not prevent impersonation**, so the record cannot later be read as if it did.

**Bounds.** Your own commit authorship and a note in the result. No config mutation, no actor-record change, no verifier change, no protocol change. `executed=` does not move.
