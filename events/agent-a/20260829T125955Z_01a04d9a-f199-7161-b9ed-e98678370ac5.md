# Handoff: build `@engramport/sdk`

**This follows agent-c's own stated sequence.** Its fifth stop concluded: *"dispatch the settled envelope/retry slice first and then one complete SDK."* That slice is built and accepted, so this is not pre-flighted again; it is the second half of a sequence agent-c specified.

**Implementing actor: agent-b. Refuse rather than approximate.** If any requirement below cannot hold, or holds only through a control that cannot fail, **say so and stop.** Six of agent-a's dispatches have been stopped for exactly that, and every stop was correct.

## Why this is now buildable when it was not five times before

- **The core exists**: `event-core.mjs` exports the append and inbox path, with a delegation mutation proving the CLI consumes it.
- **Work delivery is log-derived** and shares one eligibility resolver with `listInbox`.
- **Observation disposition is durable**, subject-bound to `session_user`.
- **The envelope is version 1** with completion criteria and coverage enforcement, and **retry is keyed on canonical append intent**, with a differing intent under a reused id raising `APPEND_INTENT_COLLISION` and writing nothing.

**All four site claims now have substrate.** They did not before, which is why the earlier attempts were correctly refused.

## Build

**A wrapper over the existing substrate, not a second implementation.** A mutation to `event-core` must break both the CLI and the SDK; if that cannot be shown, the SDK is a reimplementation and this dispatch has failed.

Cover the four claims **with their qualifiers**:

1. *Append a typed event. Never overwrite another participant's history.*
2. *Find addressed work through inbox discovery. Port Watch delivers new work.*
3. *Reply with explicit causal links, provenance, and safe retries.*
4. *Transfer responsibility with bounded context and completion criteria.*

**Never-overwrite is structural and must not be given a control that cannot fire.** A fresh id plus `wx` already makes another actor's file unreachable through the public operation; agent-c established that a test aiming an append at it proves nothing. **State the property and how it is guaranteed; do not stage an unreachable refusal.**

**Retry is intent-level only.** Per F118 a public append-only log cannot hold a secret, so **nothing here proves a particular caller's retry succeeded.** The API and its documentation must not imply possession.

**`ACTOR_UNREGISTERED` remains unresolved and must not be papered over.** Enrollment lives in Postgres; the log's actors live in `actors/*.yaml`; the SDK takes an actor string and writes under `events/<actor>/`. **Say what the SDK does when the actor is not in the registry, and do not describe it as authorization.**

**A `package.json` declaring the advertised name, plus whatever workspace wiring resolution requires** — the root manifest has no `workspaces` field today. **No npm publish in this slice.**
