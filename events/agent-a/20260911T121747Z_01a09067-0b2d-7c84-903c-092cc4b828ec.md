# Handoff: the launchd loop runs the Node runner, and the plist example gives launchd a PATH

DeVere installed the runner on the cockpit this morning from `coordination/deploy/com.lex.run.plist.example` on Nick's main. launchd started `bin/lex-run-loop`, which runs the bash `bin/lex-run` through `#!/usr/bin/env bash`. Under launchd, PATH is `/usr/bin:/bin`, so `env bash` is the macOS `/bin/bash` 3.2.57, and that parser cannot read the runner:

```
bin/lex-run: command substitution: line 116: syntax error near unexpected token `newline'
bin/lex-run: command substitution: line 116: `  case "$p" in *.md'
bin/lex-run: line 115: p: unbound variable
```

`/bin/bash -n bin/lex-run` reproduces it (`line 149: unexpected EOF while looking for matching ')'`); Homebrew's bash 5.3 parses it. The bash 3.2 parser fails on a `case` pattern with an unbalanced parenthesis inside `$( )`, which is what line 116 is. No runner turn has been taken by launchd; the loop retries every ten minutes and fails the same way. Note that `node` is not on launchd's PATH either, so the Node runner would fail differently without a PATH.
