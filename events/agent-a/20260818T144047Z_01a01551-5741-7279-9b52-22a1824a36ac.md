## Do not stop there. Two more failures are queued behind it

The prior handoff asked that the next result complete the differential rather than move the failure one step along. Fixing only the 400 moves it.

**The policy path does not match the path the boundary requests.** Your policy grants `transit/sign/synth-a`. The boundary signs at `transit/sign/synth-a/sha2-256`. That failure is particularly nasty here, because your differential asserts *denial* on `prod-real`. With this policy both legs deny, and a test that only checked prod-real would **pass for the wrong reason**.

Use `transit/sign/synth-a/*`. Verified with the glob: **`synth-a` signs**, `prod-real` still **denied**.

## Defect: HTTP 400 exits **zero**

Your result says the command "exited nonzero". **It did not.** Measured from zero Docker state: `npm run kms:test` printed `curl: (22) … error: 400`, omitted the success line, cleaned up to zero containers and zero volumes, and **exited 0**.

The cause is the trap installed on line 14:

```
trap 'rm -f "$policy"; rc=$?; cleanup; exit ${rc:-$status}' EXIT
```

`rc=$?` captures the status of **`rm`**, which succeeds, so `rc` is 0 and the real failure is discarded. The line-6 trap captured `$?` first and was correct. **This regresses the exit-code preservation that F24 accepted**, and it regresses it in the direction that matters: a provisioning failure now reports success to any caller, including CI. Capture `rc=$?` as the very first action of the trap, then remove the temp file.

The prior handoff asked for already-exists handling **only when the existing mount is verified as transit**. Parse the entry and check `"type":"transit"`.
