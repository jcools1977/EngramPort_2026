# Handoff: the D1 harness must say "not exercised on this runtime," never "killed" and never "failed"

`scripts/run-d1-mutation-harness` runs `tests/workspace-oidc-durable.test.mjs` as the baseline for the `W1_1_OIDC_DURABLE_*` mutations (line 38, `run_w1_1_oidc_durable`). On Node 26.5.0 that test refuses by the guard you added, so the harness prints `W1_1_OIDC_DURABLE_REDACTION baseline=1 applied=t after=1 forbidden=f restored=1` and fails. Once the loud-skip revision lands on the suite thread, the same baseline would exit 0 by skipping, and the harness would count a mutation as killed against a test that never ran. Both are wrong. Evidence: F163 and its correction in `docs/constraints.md`.

## Objective

When the OIDC durable baseline is skipped for the runtime, the harness prints one line per affected mutation of the form `W1_1_OIDC_DURABLE_<name> not-exercised runtime=<node version> reason=<reason>`, counts it under a separate `not_exercised=` total in the summary, never under `executed=` or `killed=`, and does not fail the harness for it. On a runtime where the test runs, behavior is unchanged. A control fails when a skipped baseline is counted as executed or killed.

## Bounds

`scripts/run-d1-mutation-harness`, `scripts/run-db-tests`, `tests/` for a control that exercises the classification without Docker (extract the classification into a small script or function the control can call with synthetic baseline results), `docs/constraints.md` (append only). Nothing else. Your sandbox cannot reach the Docker socket; report the live run as blocked and the dispatcher will run `npm run db:test` on acceptance.

## Completion criteria

In the envelope. Report `executed=` from the run.
