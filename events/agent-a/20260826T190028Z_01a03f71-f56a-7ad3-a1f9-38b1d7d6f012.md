# Handoff: make agent-c a participant instead of a tool

**DeVere's question is whether all three agents are working as the community is designed. They are not**, and ADR 0039 names why: agent-c is invoked as a subprocess on the owner's credential, can only critique agent-a's dispatches, and cannot act on its own turn. **In the product, agent-c is another builder's agent on their machine and their tokens.** This slice does not reach that. It removes the three obstacles that make the current arrangement structurally single-owner.

**1. Accept a `reply` as a review target, not only a `handoff`** (F97). `agent-c-supervisor` refuses any target whose type is not `handoff`, while `strict_relay` permits one root per thread, so **correcting or continuing anything with agent-c requires abandoning the thread and opening a new one.** It has already produced a permanent deadlock: `council-01-review` ends in an event addressed to agent-c that no lawful event can answer, and agent-c's inbox reports unactionable work on every pass, forever. A poller wired to that inbox would spin on it.

**2. Let agent-c review completed work, not only proposed dispatches.** Today the schema admits `dispatch_feasibility` and nothing else, so **the only independent check on agent-b's implementation is agent-a**, and agent-a's specifications have been the defective half repeatedly: F102 and F103 were agent-a's own errors found after acceptance. Add a result-review mode whose verdict is about the delivered work rather than the instruction.

**Do not widen this into a general recommendation surface.** F98's lesson was that a role was assigned from an org chart rather than an interface. Add exactly the second mode, keep the refusal-on-unknown-keys property that made the schema trustworthy, and say so if you think a third mode is needed rather than adding it.

**3. Let agent-c discover its own turn.** A poll that reads `inbox --actor agent-c` and reports what is open. **Notify-only, no model invocation, no credential handling**, matching the capability boundary DeVere set for the relay notifier on 2026-08-25. It must be able to distinguish an actionable turn from the F97 deadlock above, or it will report the same phantom item forever, which is the failure that motivates item 1.

**Required evidence.** Discriminating mutations for items 1 and 2. **For item 3 the control that matters is the negative one:** prove the poller stays silent when nothing is addressed to agent-c, because a watcher that cannot be observed failing is worth nothing, and a notifier that fires on the deadlock is worse than none.

**Bounds.** The supervisor, its schema, its tests, and the poller. **No live model call in tests**, use a stub. No enrollment, no SDK, no protocol change, no actor-record change, no credential written anywhere. `executed=` moves from its current observed value, which you should state rather than take from agent-a.
