# Handoff: make the SDK genuinely publishable

**DeVere asked whether the SDK is actually ready before publishing to npm. It is not, and the reason is verifiable.** Recorded as F133.

`npm pack --dry-run` produces a **3.0 kB tarball containing `package.json` and `src/index.mjs`**. That file imports `../../git-adapter/src/event-core.mjs` and `../../port-watch/src/index.mjs`, **relative paths that escape the package and are not in the tarball.** The first `import` after installation fails. **`git-adapter`, `port-watch` and `agent-c-supervisor` have no `package.json` at all**, so the dependency cannot even be declared.

**This survived the whole SDK slice because every test ran inside the repository, where those paths resolve.** The acceptance proved a mutation to `event-core` breaks both consumers, which established genuine coupling and **simultaneously established the coupling that makes the package unshippable.** The same evidence read both ways.

## Build

**Make `@engramport/sdk` installable and functional from a clean environment.**

**The fork is yours to decide and justify: separate published packages, or a bundled single artifact.** Separate is honest about the architecture and means publishing more than one name. Bundling avoids that and duplicates code into the artifact. **Say which you chose and what it costs**; agent-a has no preference and would rather not impose one badly.

**Whatever you choose, the manifest must be complete enough to publish honestly**: a `files` allowlist so nothing unintended ships, plus `license`, `repository`, and a package README. **Do not remove `"private": true` in this slice.** Publication is DeVere's act under ADR 0036, and the package must be proven first.

## The control that matters, and no in-repository test can substitute

**Pack the package, install the tarball in a clean directory outside this repository, import it, and exercise a real operation.** That is the only proof, because **the defect is precisely that the repository is present.** A package is not proven by its tests passing where it was written.

**Make that a repeatable control, not a one-off check**, with a discriminating mutation: restore an escaping relative import and show the clean-directory test fails while the in-repository tests still pass. **That contrast is the finding, and the control should make it permanent.**

## Evidence

- The clean-directory install imports and performs a real append against a temporary log.
- The mutation above fails the clean test and passes the in-repository tests.
- The repository's own 435 events verify unchanged and existing SDK tests still pass.
- `executed=` moves from its observed value, which you state.

**Bounds.** Package manifests, packaging structure, the clean-install control, and its mutation. **No npm publish**, no `private` removal, no protocol or envelope change, no site copy change.
