# Handoff: surface the provider's diagnosis and refuse a malformed credential

**This is a defect found by running the agent-c harness for the first time**, recorded as F94. It cost an out-of-harness manual request to diagnose. It is unblocked and does not depend on any decision reserved to DeVere.

**What happened.** The 1Password field held the entire assignment line, `XAI_API_KEY=xai-...`, 96 characters. `requireResolvedCredential` refuses only values beginning `op://`, so that passed. The call then failed as `MODEL_CALL_FAILED`, discarding the provider's own message, "Incorrect API key provided."

**Deliver two changes.**

1. **Refuse a credential that is not a bare key** with a code distinct from `CREDENTIAL_UNRESOLVED`, so "you stored the wrong shape" is never reported as "you stored a reference." An assignment line and embedded whitespace are the two observed shapes. **Do not validate against a vendor prefix**: `xai-` is not a stable contract and a check that guesses the provider's format will fail closed on a valid key later.
2. **Carry the provider's HTTP status and error text into the raised failure**, so the next diagnosis needs no manual request.

**Required evidence.** Paired positive and negative per change, each with a discriminating mutation, and one further control that matters more than either:

**Prove the surfaced text cannot leak the key.** Drive a stub `fetchImpl` whose error body contains the credential verbatim, which is exactly what an echoing or misconfigured provider does, and show the result is `CREDENTIAL_OUTPUT_REFUSED` through the existing `assertNoCredential` rather than a leak. Then remove that routing and show the credential does reach the output. **Change 2 widens what reaches an error string, so it must not be accepted on the strength of the guard already existing** at `packages/agent-c-supervisor/src/index.mjs:30`.

**Bounds.** No live xAI call: every test uses a stub `fetchImpl`. No credential in any tracked or untracked file, no vault edit, no protocol change, no new event type, no SDK, no claim operation. `executed=` moves from **108** on observed execution.
