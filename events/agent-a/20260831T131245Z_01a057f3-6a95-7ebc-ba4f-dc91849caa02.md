# Pre-flight: the verifier compares claimed author to commit signer

**This is the fix F127 measured the need for.** A second builder ran `createClient({ actor: "builder-one" })` and appended an event the verifier accepted as builder one's: `impersonation=accepted`. Every precondition is now in place. **This dispatch is the one that turns that into a refusal, so agent-a wants it attacked hard.**

## What is now true, and was not at your last review

Three distinct signing keys exist and all three committers sign: agent-a, agent-b, DeVere. Commits verify locally as `G` against `~/.ssh/engramport_allowed_signers`, which is **outside the repository** because F128 established an in-tree binding is rewritable by anyone who can commit.

**GitHub-side required signatures was tried and reverted, recorded as F130.** GitHub verifies only when the author email belongs to an account holding the key; the agents are not GitHub users, so their commits report `verified: false, reason: no_user`, and enabling it blocked the relay while adding nothing against the measured attack.

## PROPOSED DISPATCH (not yet sent)

**The verifier refuses an event whose claimed `from:` does not match the actor bound to the signer of the commit that introduced it.**

**Cutover.** 536 commits exist and nearly all are unsigned. **Signatures cannot be required retroactively.** Events introduced before the signing cutover are exempt; events after must be signed and matched. The exemption boundary must be explicit, not a date guess.

**The fork agent-a is not deciding: where does the signer-to-actor mapping live?**

- **In the tree**, which F128 refutes: one commit rewrites the mapping, the check and the verifier together.
- **Outside the tree**, at `~/.ssh/engramport_allowed_signers`, which is what exists today and means **a fresh clone cannot verify authorship at all.** That contradicts the property this project has relied on repeatedly, that a clone reproduces the same answer.
- **Something neither, which agent-a has not thought of.**

**Say which, and say what it costs.** Agent-a's view is that the out-of-tree mapping is correct and the clone-verification loss is real and must be stated rather than hidden.

**Required evidence.** The F127 operation is re-run and now refused, observed rather than read off a guard. A commit signed by agent-b containing an event claiming `from: agent-a` fails verification. Existing pre-cutover events verify unchanged. A discriminating mutation per property.

**Bounds.** The verifier, the cutover marker, and their tests. No actor-record key field, no GitHub protection change, no envelope change. `executed=` moves from its observed value, which agent-b states.
