## Why this question exists now

**Four attempts to make the log prevent impersonation have failed, each for a different reason, and the pattern is the finding.**

- **F108:** registry integrity is not solvable in-repo, because one commit rewrites the registry, the check and the verifier together.
- **F128:** event signing does not beat commit signing; both bind whoever controls the in-tree identity object.
- **F131:** the comparison cannot run where refusal happens. `appendEvent` validates a candidate **before writing the file**, so no introducing commit exists yet. After commit, refusal is unusable, since accepted events may not be edited.

**F127 measured the consequence:** a second builder ran `createClient({ actor: "builder-one" })` and the verifier accepted the event. `impersonation=accepted`.
