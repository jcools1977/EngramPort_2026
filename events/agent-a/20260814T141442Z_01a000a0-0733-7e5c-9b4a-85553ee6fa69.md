## Objective

Implement **W0-2, the dry-run executor**: execute a compiled workspace setup plan in dry-run mode, producing the complete step transcript with no side effect.

This is the sole eligible implementation item. WIP remains one.

## Why this one

It is the highest-priority task that can be **honestly finished** in the current environment. Its entire acceptance is about proving the absence of side effects, which needs Node and nothing else. There is no part of it that ends in `UNVERIFIED`.

That criterion did the selecting. PW2 onward and the remaining v0.1 findings all have halves that cannot be proven under C1, and I would rather hand you work that can be completed than work that can only be written.

W0-1 is accepted and closed, so `compileSetup` is a stable foundation.

## Scope

From `docs/plan/workspace-setup-wizard-tasks.md`, task W0-2.

1. **Dry-run execution of a compiled plan.** Takes the output of `compileSetup`, walks the ordered steps, and produces a transcript. Performs no real work.
2. **Transcript contents.** Per step: `step_id`, `kind`, `action_digest` where consequential, the `consequential` flag, and a declared effect describing what a real run would do. The transcript is data, not prose.
3. **No side effects, structurally.** Dry run must not write outside a caller-supplied temporary directory, open a network connection, touch a database, or shell out. Prefer a design where the capability is absent rather than one where it is present and declined.
4. **Parity.** Dry run and a real run must produce the same step sequence for the same plan. Since no real executor exists yet, express this as a shared ordering path that both will use, and test that the dry-run sequence equals `compileSetup`'s order exactly.
5. **Refused plans cannot be dry run.** A plan `compileSetup` rejects must not reach the executor.

Out of scope, and do not build: any real execution, provisioning, GitHub call, database access, W1 session or delegation work, approval grouping, and anything in Port Watch, Re:PORT, or onboarding. Do not touch `migrations/`.

## Tests and acceptance criteria

**Positive**

1. A valid plan produces a transcript covering every compiled step, in `compileSetup` order, with no step missing or added.
2. Every consequential step's transcript entry carries its `action_digest` unchanged from the compiled plan; non-consequential steps carry none.
3. Dry-run output is deterministic: same plan, same transcript, across runs.
4. The transcript's step sequence equals the compiled plan's step sequence exactly.

**Negative**, each asserting the specific error or observation

5. **The headline control: no side effects.** A dry run of a plan whose steps describe provisioning, a GitHub pull request, and a history import performs zero filesystem writes outside the supplied temporary directory, opens zero network connections, and starts zero subprocesses. Assert **zero**, and make the test fail if any is attempted rather than inferring from absence of output. Instrument the boundary rather than trusting it.
6. A plan rejected by `compileSetup` cannot be dry run: the executor refuses with a named error and produces no transcript.
7. A transcript entry is never produced for a step absent from the compiled plan.
8. Feeding the executor a hand-built step list that never passed `compileSetup` is refused, so the compiler cannot be bypassed.

**Additional**

9. Every negative has a paired positive control, and both are reported.
10. Runs from a clean checkout with one documented command, Node only, no new dependency, no network. State the Node version.
11. `npm run setup:test`, `npm run watch:test`, `npm run welcome:test`, `npm run db:static-test`, and `npm run proof` all still pass.
12. No secret in any fixture.
