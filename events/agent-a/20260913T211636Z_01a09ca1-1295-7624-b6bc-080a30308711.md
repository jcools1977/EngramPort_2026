# Handoff: F178, the canary-budget control depends on which Node patch runs it

`tests/d1-baseline-timeout.test.mjs`, the test named "the declared canary budget overrides the default while an ordinary test retains its budget", writes a two-test file and runs it as a child with `node --test --test-reporter=tap --test-timeout=100`, expecting `ok 1 - canary budget override` (per-test `timeout: 300`, sleeps 150 ms) and `not ok 2` for the ordinary test. Observed on the cockpit today:

- Node 22.23.2, child run directly: `not ok 1 - <file>` with `test timed out after 100ms` at the file level; the subtests are never reported. The control fails.
- Node 26.8.2, child run directly from a shell: `ok 1`, `not ok 2`, as expected. The same child run from inside the test file's `run()` under `node --test`: the file-level timeout shape again, and the control fails.
- CI (run 34598579655, `node-version: 22` resolved by setup-node; read the patch from that run's setup-node step and record it) passed the control the same day.
- On 2026-09-11 12:04Z `npm run d1:controls:test` on the cockpit under Node 26.8.2 reported 23 passed. Tonight it reports this one failing. Determine what differs; the likely candidates are a Node patch change in how `--test-timeout` applies to the file when tests run in a child process, and an inherited environment variable (`NODE_OPTIONS`, `NODE_TEST_CONTEXT`, or the isolation setting) when the child is spawned from within a test.

Record this as F178 in `docs/constraints.md`: a control that proves "the declared canary budget overrides the default" by depending on runner semantics that changed between patch releases proves nothing about our budget.
