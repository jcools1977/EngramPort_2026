## Defect 2: the provisioning script cannot fail, and says so anyway

```
for i in $(seq 1 30); do curl -fsS …/sys/health >/dev/null && break; sleep 1; done
curl -fsS -X POST … /v1/sys/mounts/transit >/dev/null || true
echo 'Vault 1.17 provisioned and health-checked; synthetic transit path ready'
```

Three separate faults, all reproduced:

1. **The retry loop cannot fail.** If all thirty attempts fail the loop simply ends and the script continues. Under `set -e`, a command in a `&&` list does not trigger exit.
2. **`|| true` swallows the transit mount result.** Incomplete setup exits zero.
3. **The success line is unconditional.** I observed `curl: (56) …` followed immediately by `Vault 1.17 provisioned and health-checked; synthetic transit path ready` and **`EXIT=0`**.

That is a check that reports success without being capable of reporting failure, which is the one thing this project treats as worse than no check. Require: bounded retries that **exit nonzero** when exhausted, no `|| true` on a required step, container diagnostics on failure with no secrets, and a success line that is only reachable when every step actually succeeded.

## Defect 7: UUIDv7 has no injectable clock and is not monotonic within a millisecond

`uuidv7()` calls `Date.now()` directly, with no injection point, so the timestamp **cannot be bound to the database clock** the durable custody store will require. Separately, 328 mints inside one millisecond came back in **random order**, because `rand_a` is random rather than a counter. RFC 9562 permits that, but a custody log wants ordered references. Add a clock parameter and a same-millisecond counter.

## Correction to my own earlier finding

F19 recorded that removing the rollback left the round-one suite green, and I reported that as a weak assertion. The assertion was weak, but **that was not the reason**, and I diagnosed it wrongly.

Round-one `uuidv7()` derived its entropy from the first 16 bytes of a fresh RSA-2048 SPKI DER. **Those bytes are a fixed ASN.1 header, identical for every RSA-2048 key**, so the function returned a **constant**. Six mints produced **one distinct reference**, and each custody row overwrote the last, which is why the store never grew and the size comparison never diverged. M9's deterministic collision refusal was violated by construction.

**Your `randomUUID` rewrite fixed this**, and the measurements above confirm it: 0 collisions in 20,000. Recorded so the register carries the real cause.
