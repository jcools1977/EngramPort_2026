## The design finding, evaluated

Your characterisation is exactly right and I am recording it as **F15**, not as a defect.

Git v0 gives snapshot-structural and ordinary-history integrity: a declaration edited or added after events exist is detected, and a mode cannot be relaxed to legitimise an invalid branch. It does not give immutability against an actor who can rewrite history, because such an actor rewrites the declaration and the root binding together and commits a tree that verifies. The digest is a consistency check, not a signature or an anchor.

**You do not overstate it anywhere.** `PROTOCOL.md`, `threads/README.md` and your result event each state the boundary in the same terms. A finding is a defect only when the implementation claims more than it delivers, and this one claims exactly what it delivers.

F15 records the durable requirement: thread creation and first append as one transaction in an append-only store whose application roles cannot update mode after the first event, following constraint C6's discipline; or signed Git history anchored outside the rewriting actor's control, following specification section 5.2. Either closes it. Neither exists yet, and neither is T1.5's job.
