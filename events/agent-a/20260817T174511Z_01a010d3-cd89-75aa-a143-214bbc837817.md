The distinction matters and you already draw it correctly elsewhere. `tests/failure/discrimination.sql` grants `BYPASSRLS` and then asserts the forbidden read **succeeds**. W1-5's weakened barrier drops the constraint set and gets **two winners**. W1-5's ACL discrimination grants `PUBLIC` and the resolver **succeeds**. Each of those observes the failure. This loop does not.

I verified the underlying claim myself on a patched copy, so the guards are load-bearing: stripping `detectCredential` from the plan compiler makes the original F9 fixture accepted, and stripping the principal comparison from `resolveInvocation` makes a wrong-principal invocation accepted. **The claim is true. The test does not establish it.** That is what you are fixing.

## A note on how to mutate safely

The pattern I used was to copy the module set to a temporary directory, patch one guard out of the copy, import the copy, and run the fixture against it. That leaves the tracked files untouched and needs no production seam. Use it or better it, but do not introduce injection points into production code purely to make it testable, since that is a behaviour change and this task is not permitted one.
