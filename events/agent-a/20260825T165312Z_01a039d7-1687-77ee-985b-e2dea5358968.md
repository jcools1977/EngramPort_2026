# Dispatched: the real provider composition, bounded to the loopback redirect

**DeVere has authorized real Google discovery, JWKS retrieval, token exchange and ID-token verification.** ADR 0033, digest `3137bcd6e00ba3892006ca38e3d2f849232ff320eaedf5024fc1e261071a7eff`.

**This is the first authorization in this project permitting a real provider, a real credential and real network egress.** The standing synthetic-only rule is **narrowed for this scope and stays in force everywhere else**, so treat the boundary as the load-bearing part of the dispatch.

## Bounds

- **Google only, the F83 client only.** No other issuer, no second client, no broker.
- **Loopback redirect only**: `http://localhost:8787/auth/callback`. **Production deployment — the `app.engramport.com` Custom Domain, `wrangler secret put`, any Cloudflare API call — is a separate authorization and is not granted.**
- **Custody unchanged.** The secret reaches a local run through `op run --env-file` resolving `op://` references at launch, so plaintext exists only in the launched process. **A shell variable is refused**: it enters history and the process table. The reference file holds references, never values, and the item name contains spaces so it must be quoted.
- **`openid` only.** No `email`, `profile`, `offline_access` or refresh token.
- **No retention** of the ID token, any access token, or the full claim set.

## Dispatched

1. **Discovery against `https://accounts.google.com/.well-known/openid-configuration`**, with the **authorization, token and JWKS endpoints taken from the document rather than derived**. This closes **F80** — the `{issuer}/authorize` convention is wrong for Google, whose token endpoint is on a different host entirely. **The issuer stays pinned to configuration; only endpoints come from discovery, and a document whose `issuer` disagrees with configuration is refused.**
2. **Real JWKS retrieval with a genuine key lifecycle** — refresh on unknown `kid`, overlapping active keys, key disappearance, cache expiry. **F73 recorded that the fixture's `status: active|retired` label is non-standard and no real JWKS carries it**, so the accepted rotation control must keep passing **without** that label being what makes it pass.
3. **Real token exchange** at the discovered endpoint using the registered client and the resolved secret.
4. **Dispose `azp`** — F73's second open question. **Decide it against tokens Google actually issues**: either prove a single audience always, or implement the authorized-party rule with its own control. **This is now answerable by observation rather than speculation.**
5. **A `sub` capture path.** ADR 0030 requires the subject come from a token issued to **this** client. Report it as a **recorded value, not a claim of enrollment** — enrolling it is a separate step.

## Evidence

Paired positive and discriminating mutation each, **and the distinction that matters most here**: a real-provider observation is **additional evidence, never a replacement** for a synthetic control. **The ten verifier mutations and seven Durable Object controls keep running unchanged and must not be re-pointed at Google.** `executed=` moves from **98** only on observed local-control execution; **no real-provider observation may be counted as a local control.**

## What this cannot establish, restated because it will be tempting

**Nothing here proves the provider's enrollment judgement is sound.** F73's conclusion stands: criterion 1's closure is **a tested technical chain plus a named operational trust statement**, never a claim that authentication became trust-free. F74 narrows it further — DeVere administers the Workspace **and** is the founder, so the provider's judgement and EngramPort's registration partially collapse into one person. **Do not describe a successful login as discharging the trusted-session caveat.**

**If any bound here is unsatisfiable, return it rather than working around it.** That instruction has caught four defects in my dispatches and every one was mine.
