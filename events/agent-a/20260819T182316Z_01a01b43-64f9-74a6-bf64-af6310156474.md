## The contract

### 1. Fault-control authority

Two transaction-local GUCs, read **only** when the connecting role is exactly `engram_maintenance`. Declare at the top of the function:

```sql
stage text := CASE WHEN session_user='engram_maintenance'
  THEN nullif(current_setting('app.d1f_stage',true),'') ELSE NULL END;
forced text := CASE WHEN session_user='engram_maintenance'
  THEN nullif(current_setting('app.d1f_forced_reference',true),'') ELSE NULL END;
cname text;
```

**`session_user`, never `current_user`.** Inside a `SECURITY DEFINER` function `current_user` is the owner, so a `current_user` test would grant the control to every caller. This mirrors the `session_user = 'engram_maintenance'` gate already used by `bootstrap_workspace` in `0001`.

**Unknown stages fail closed**, immediately after the authority check and before model derivation:

```sql
IF stage IS NOT NULL AND stage NOT IN ('after_custody_row','after_reference_bind','pause_before_reference')
  THEN RAISE EXCEPTION 'D1F_STAGE_UNKNOWN' USING ERRCODE='42501'; END IF;
```

**Proven:** maintenance with `bogus` → `D1F_STAGE_UNKNOWN`; maintenance with no stage → normal mint; `engram_app` → `permission denied for function`, `EXECUTE=false`, **PUBLIC 0 rows**; and **`postgres`, whose `session_user` is not `engram_maintenance`, has the stage set and the mint proceeds normally**, which is the positive control showing the gate binds to the role rather than the variable.

### 2. M11 and M12 stages, at the design boundaries

Design section 6 orders the transaction: **6** insert the custody row, **7** mint the reference, **8** insert the binding, **9** insert the audit record. So M11 sits **after 6 and before 8**, and M12 **after 8 and before 9**. Both inside the real transaction, not a wrapper, and no `SAVEPOINT`.

```sql
-- immediately before INSERT INTO minted_references
IF stage='after_custody_row' THEN RAISE EXCEPTION 'D1F_FAULT_AFTER_CUSTODY_ROW' USING ERRCODE='42501'; END IF;
-- immediately before INSERT INTO custody_audit
IF stage='after_reference_bind' THEN RAISE EXCEPTION 'D1F_FAULT_AFTER_REFERENCE_BIND' USING ERRCODE='42501'; END IF;
```

**Proven:** each raises its named error and **rolls back the entire transaction**, leaving `custody_rows=0 minted_references=0 custody_audit=0`.

### 3. Deterministic collision control

No new caller parameter and no production override. The forced value is the same maintenance-only, transaction-local GUC, and it must still be a canonical synthetic reference for the requested namespace:

```sql
IF forced IS NOT NULL THEN
  IF forced !~ ('^epr:'||p_namespace::text||':[0-9a-f]{8}-[0-9a-f]{4}-7[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$')
    THEN RAISE EXCEPTION 'D1F_FORCED_REFERENCE_INVALID' USING ERRCODE='42501'; END IF;
END IF;
ref := coalesce(forced, ref);
```

Place it after the normal `ref := format(...)` so ordinary generation is untouched. **Proven:** a non-canonical value raises `D1F_FORCED_REFERENCE_INVALID`, and the control is inert for any role whose `session_user` is not `engram_maintenance`.

### 4. Collision error distinction

Replace the absent handler with one that reads the constraint name and never flattens:

```sql
EXCEPTION WHEN unique_violation THEN
  GET STACKED DIAGNOSTICS cname = CONSTRAINT_NAME;
  IF cname='minted_references_pkey' THEN RAISE EXCEPTION 'REFERENCE_COLLISION' USING ERRCODE='23505';
  ELSIF cname='custody_single_active' THEN RAISE EXCEPTION 'CUSTODY_IDENTITY_ACTIVE' USING ERRCODE='23505';
  ELSE RAISE; END IF;
```

**Proven:** a forced duplicate reference gives **`REFERENCE_COLLISION`**; a second mint on an active identity gives **`CUSTODY_IDENTITY_ACTIVE`**; any other uniqueness violation re-raises unchanged. That closes the conflation I raised when every `23505` mapped to one name.

### 5. Genuine concurrency

One additional maintenance-only stage is the minimum needed to make the overlap deterministic, mirroring `app.test_bootstrap_pause` from `0001`:

```sql
IF stage='pause_before_reference' THEN PERFORM pg_sleep(2); END IF;
```

Two independent `psql` sessions: A sets `app.d1f_stage='pause_before_reference'` and holds inside the transaction; B starts half a second later and races to the datastore barrier.

**Proven:** **A commits with a reference, B loses with `CUSTODY_IDENTITY_ACTIVE`.** Exactly one commit, one named loser.

### 6. Residue, per table, with attempt-specific identifiers

Give each attempt a distinguishable `key_locator`, then query each table independently. **Never compare two counts to each other**, which is F19.

**Proven** with `vault:winner` and `vault:loser`: `custody_rows` with the loser's locator **0**, `minted_references` joined to loser rows **0**, `custody_audit` **1 row, the winner's**, and the winner's own row present. Same zero-in-all-three result after both M11 and M12.

### 7. Discrimination

**Proven both directions:** with `minted_references_pkey` present, a forced duplicate raises `REFERENCE_COLLISION` and **1** reference is stored; after dropping the barrier in a disposable copy, the same forced duplicate is **accepted and 2 identical references are stored**. Verify each mutation applied before trusting it, and restore afterwards.

For the rollback boundaries, neutralising a `RAISE` simply removes the fault rather than producing partial residue, because PostgreSQL's transaction semantics are what guarantee atomicity. State that as an individually justified structural limitation rather than manufacturing a partial-commit path; inventing a `SAVEPOINT` to make residue observable would violate design section 6.
