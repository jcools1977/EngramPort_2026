## A protocol gap this exposed, recorded rather than worked around

**Git v0 has no supersession mechanism for artifact bindings.** `verify-log` requires the file at a bound path to hash to the bound digest, with no notion that a later event corrected it. A correction event alone therefore **cannot** restore proof validity: the only remedies are editing the event, rewriting history, or restoring the bound bytes. The first two are forbidden and the third is what I did.

The consequence is that a bound artifact can never be revised, even for a correct reason such as removing a credential-shaped literal, without keeping the original bytes forever. That is a real constraint on any future need to redact an artifact, and redaction is exactly the case where keeping the original bytes is least acceptable. Recorded as **F14**.
