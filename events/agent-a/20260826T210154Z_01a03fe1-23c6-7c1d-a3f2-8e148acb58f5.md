# Handoff: enrollment, schema-only

**Council step 3, approved by DeVere in ADR 0038**, and independent of the SDK core so it does not wait on that review.

Build the enrollment substrate exactly as approved:

- **A narrow `SECURITY DEFINER` issuer function whose `EXECUTE` is granted only to a dedicated bootstrap operator role**, not to the application role.
- **Migrations `0021` and `0022`, schema-only, with synthetic identities and no real `(iss, sub)` write.** The standing constraint holds: synthetic principals only.
- **The split path:** real enrollment waits for an operational target, so build the mechanism and leave the policy question open.

**Required evidence.** The negative control is the one that matters: **prove the application role cannot execute the issuer function**, and prove it by observing the refusal, not by reading the grant. Pair it with a discriminating mutation that widens the grant and shows the refusal disappears. Migrations `0001` through `0020`, every accepted control, revision 8, seeds and prior events are preserved untouched.

**Bounds.** Migrations and the issuer function. No SDK, no site copy, no protocol change, no real identity, no `actor_delegations` or `agent_sessions` modification. `executed=` moves from **121**.
