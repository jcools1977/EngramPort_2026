# Handoff: a pre-push identity guard that refuses a commit whose signer is not its author

Seven commits this week carried an agent's author identity and DeVere's signing key (five in `docs/security/accepted-identity-mismatches.json`, two more last night caught before push and recommitted). Every one was made by agent-a's hand: a plain rebase, a plain `git commit` in the main tree. The identity control (`tests/identity-control.mjs`) catches them after the fact and CI goes red. The guard refuses them before they leave the machine.

## Objective

1. **`scripts/git-hooks/pre-push`**, a hook honoring git's pre-push protocol: it reads `<local ref> <local sha> <remote ref> <remote sha>` lines on stdin, and for every commit in `remote_sha..local_sha` (all reachable commits when the remote sha is all zeros, bounded by `--not --remotes` so a new branch does not walk the whole history) runs the same query the identity control runs, `git show -s --format=%H|%G?|%ae|%GS` under `gpg.ssh.allowedSignersFile`. It refuses the push, exit 1, naming each offending commit with its author and signer, when: the signature does not verify (`%G?` is not `G`), or the author email differs from the signer principal, unless that sha is in `docs/security/accepted-identity-mismatches.json`. Nothing else is checked. The allowed signers file is the one git is configured with (`gpg.ssh.allowedSignersFile`), falling back to `~/.ssh/engramport_allowed_signers`; if neither exists, refuse with a message saying so, never skip. Bash, no dependencies beyond git.
2. **Controls in `tests/pre-push-guard.test.mjs`**, run entirely in a temporary repository with keys generated by `ssh-keygen` for two synthetic principals and a synthetic allowed-signers file, a bare local remote, and the hook invoked directly with the protocol lines on stdin and `cwd` in the fixture. Observed both ways: a commit authored as principal A and signed with principal B's key is refused with the sha, author, and signer in the output; a commit authored and signed as A passes; an unsigned commit is refused; a mismatched commit whose sha is in a synthetic accepted record passes; a push of an already-pushed range (remote sha equals local sha) passes with nothing to check; a new branch checks only the commits not on any remote ref. Mutation: remove the author/signer comparison in a copy of the hook and show the mismatched commit passes, then restore.
3. **Wire it into `npm test`** through the existing d1 controls or wherever `commit-identity.test.mjs` runs, and add one sentence to AGENTS.md item on identity saying the hook exists and where it is installed from. Installation itself (the estate's `core.hooksPath` points at DeVere's dotfiles, which must delegate to this script) is the dispatcher's; do not touch anything outside this repository.

## Bounds

`scripts/git-hooks/pre-push` (new), `tests/pre-push-guard.test.mjs` (new), `package.json` scripts if needed to include the test, `AGENTS.md`. No change to `tests/identity-control.mjs` or the record. Commit as instructed.
