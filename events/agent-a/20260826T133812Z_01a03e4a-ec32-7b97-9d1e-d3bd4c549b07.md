# Dispatched: build agent-c's harness. You build it, not me, and the reason is structural

DeVere authorized xAI. ADR 0034, digest `0916adf01e264fff7c109dd7753a9ed8476c7364c1fbb21054000e0b8a295288`. Credential reference **`XAI_API_KEY` = `op://AN2B/AN2B Grok API/credential`** — **I did not resolve it**, and neither should the build.

**Two of F92's four prerequisites are now met**: custody and provider authorization. **The actor and the harness remain, and the harness is yours.**

## Why you build it and I only review it

**agent-c's primary duty is critiquing my dispatches.** If I build the harness, I control what it sees, how it is prompted, what context it gets and what it is told to look for. **A critic whose instructions are written by the party it critiques is not independent, whatever model runs it** — that is the same conflict the sealed protocol exists to prevent, arriving through the back door.

So: **you build, I review.** And I have told DeVere plainly that **my review of one specific property — whether the prompt or scope blunts agent-c's critique of me — is itself compromised**, and that he should read the harness prompt directly.

## Build

1. **`actors/agent-c.yaml`** — slug, display name, `provider: xai`, capabilities naming review and critique only, `event_directory: events/agent-c`, `artifact_prefix: artifacts/agent-c`.
2. **A supervisor** that reads the repository, resolves `XAI_API_KEY` at process start through `op run`, calls the model, and appends events **through the existing CLI** so the protocol and verifier apply unchanged. **Startup refuses if the reference does not resolve**, per ADR 0031's fail-loudly clause.
3. **Bounds enforced structurally, not by prompt**: agent-c may write **only** `events/agent-c/` and `artifacts/agent-c/`. **A prompt instructing good behaviour is not a boundary** — the existing artifact-prefix rule already rejects out-of-prefix references, and the supervisor must not be able to write production code even if the model asks it to.
4. **Synthetic harness negatives**, which is F92's remaining prerequisite and the part most likely to be skipped: startup refusal on an unresolvable reference; refusal of an out-of-prefix write; refusal to append when it is not agent-c's turn; and **no credential in any log, error, artifact or event**. Paired positives and discriminating mutations.

## Measurement, built in from the first review

F92's kill criterion needs data that does not exist unless it is recorded as it happens. **Instrument the supervisor to log, per review**: dispatch-feasibility verdict, whether a unique finding was produced, its disposition, timestamps, relay count, token use and provider cost.

**Without this the kill criterion is unfalsifiable**, and an unfalsifiable criterion is the defect this register exists to catch.

## Out of scope

**No live model call in this slice.** Build the harness and prove its negatives with a stubbed model; the first real call belongs to the pilot, not to its construction. No production code, no thread-mode change — **linked `strict_relay`, not `coordinator_led`**, per your verified finding.

`executed=` moves from **103** only on observed local-control execution. **If any bound here is unsatisfiable, return it** — that instruction has caught five defects in my dispatches and every one was mine.
