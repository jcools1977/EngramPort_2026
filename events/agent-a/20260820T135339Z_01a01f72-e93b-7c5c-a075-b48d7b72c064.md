## Architecture decision you do not have to make

**This is the first Node-to-PostgreSQL runtime path in the repository.** `package.json` has no PostgreSQL driver: `drizzle-orm` is present but unbacked, and every database test today runs through `psql` inside the compose container. So a driver enters the tree.

**Decided: add `pg`, pinned to an exact version, as a production dependency.** It is the canonical client, pure JavaScript with no native build, and it exposes the two things this slice needs — a pool with a release hook, and per-connection session state. I considered and rejected driving `psql` through `child_process`: it would make the pooled-connection reset property, which is half the discrimination below, untestable in the shape it actually fails. Commit the lockfile change with the slice and keep `npm test` green.

## The contract

Add a session-binding adapter alongside `packages/git-adapter/src/custody-service.mjs`. It owns connection acquisition and principal binding, and nothing else in this slice.

1. **The principal comes from a verified authentication result, never from caller input.** The mint entry point takes `(request, session)`. Any `principalId`, `tenant_id` or `project_id` appearing in `request` is ignored, and no code path may read a principal from the request object.
2. **Refuse when unbound.** No verified session means a named refusal before any connection is acquired: `SESSION_UNBOUND`. Not a generic throw, not a null return.
3. **Bind on the privileged session.** Connect as `engram_maintenance` and set `app.principal_id` from the verified identity. Set it **transaction-locally**, `set_config(name, value, true)`, so it cannot outlive the mint transaction. Design section 11's `ctx` carries the authenticated principal and the transaction handle and no tenant, project or namespace authority; keep it that way — tenant and project stay derived by `derive_mint_membership`, which D1E already proved.
4. **Reset on release.** Every connection returned to the pool is scrubbed, `DISCARD ALL` or an explicit reset, so a principal cannot survive into the next checkout.
5. **Do not touch the mint SQL.** `0001` through `0011` stay byte-identical. If you believe a migration is required, return that finding instead of writing one.

## Required discrimination

F17 applies. Each property needs a mutation that makes the control fail, not a passing negative test.

6. **Caller-asserted principal.** Authenticate as principal Y, send a request whose body carries principal X, mint, and read `minted_by_principal_id` from the live row: it must be **Y**. Remove the guard that ignores request-supplied identity and the same fixture must yield **X**.

8. **Transaction scope.** After the mint transaction ends, `current_setting('app.principal_id', true)` on that connection must be empty. Change the `set_config` third argument to `false` and the value must survive, which is the mutation that proves the scoping is load-bearing rather than incidental.
