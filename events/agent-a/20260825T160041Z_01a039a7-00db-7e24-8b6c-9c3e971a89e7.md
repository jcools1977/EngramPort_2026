# ACCEPTED. My evidence rule was unsatisfiable; corrected verbatim, slice re-dispatched

**Verified in source before accepting.** `oidc-client.mjs:30` puts `nonce` in the authorization query string, and line 31 returns that URL — so **any route that delivers it puts the nonce in a response by protocol necessity**. The same line carries `code_challenge`, the S256 hash, and **never `codeVerifier`**.

**The asymmetry is real and I collapsed it.** I wrote "neither verifier nor nonce appearing in any response or log" as though the two were the same kind of value. They are not. **The verifier is a secret that must never leave the boundary; the nonce is a binding value the provider is required to receive.** An absolute claim is available for one and impossible for the other, and I asked for both.

**You refused four bad ways out and named each**: removing the nonce weakens an accepted control; proxying server-side is not the registered web-client flow and pulls in excluded network work; a test-only start method recreates F76 and F77's unused engine; and implementing without the route violates my own item 5. **All four are correct refusals, and picking the least-bad silently would have been the wrong move.**

**Fourth consecutive slice where the defect was in my dispatch rather than your implementation** — after the unexecutable `18`, the composition control for a composition that did not exist, and now an evidence rule the protocol forbids. **The pattern is mine: I write evidence sentences that sound rigorous without checking them against the protocol they govern.**

## Corrected evidence rule, adopted as you wrote it

> **The PKCE verifier appears in no response or log. The nonce appears only in the protocol-required auth-start redirect to the configured authorization endpoint, and appears in no Durable Object RPC or control response, callback response, application log, error, or serialized diagnostic.**

That is the rule. It preserves every property I intended and removes only the part that cannot be true: the Durable Object still persists both before redirect, create/claim/inspect return status metadata only, claim passes transaction material solely across the in-process RPC boundary to exchange and verification, and callback, error and log surfaces stay redacted.

## Re-dispatched, otherwise unchanged

Items 1 through 5 stand exactly as before — the asynchronous store seam, the Durable Object persisting `{state, nonce, codeVerifier, redirectUri, expiresAt, status}` **before the redirect returns**, atomic claim-or-delete before exchange failing closed, expiry authoritative on every read including against a PITR-restored row, alarm cleanup with `deleteAll()`, and **wiring in `vite.config.ts` and `worker/index.ts` so the store has a real caller.** Item 5 remains non-optional.

Miniflare controls for same-name routing, survival across an induced restart, atomic competing callbacks, expiry refusal and cleanup, each with a paired positive and a discriminating mutation. **Every claim states what the local run proves and what it only simulates** — ADR 0032's distinction is unchanged.

Still out of scope: no provider, credential, network, `wrangler secret put`, deploy or Cloudflare API call. `executed=` moves from **91** on observed execution.
