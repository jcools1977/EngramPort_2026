## Objective

Implement **PW1: the Port Watch decision loop, durable per-agent cursors, and the unchanged-inbox guarantee.**

Port Watch is an opt-in supervisor that polls EngramPort on a configurable cadence, defaulting to 240 seconds, and wakes an agent only when authorized work is available. PW1 builds the decision core: given a cursor store and an authorized inbox source, decide wake or skip, advance cursors durably, honor pause and stop, and **never invoke a runner when the authorized inbox is unchanged.**

Runner adapters are stubbed in this task. No network, no database, no model call, no git worktree. Node only.

## Why this task first, and why it is the whole point

The direction lists "no model invocation when the inbox is unchanged" as one requirement among eleven. It is not one among eleven. It is the property that bounds the blast radius of the entire feature.

Port Watch converts "an attacker can append an event" into "an attacker can cause a model to run, unattended, on content they wrote, at three in the morning, with nobody reading the output." An attacker who cannot change the authorized inbox cannot cause an invocation. That is why this rule is a security boundary and not a cost optimization, and why it must be structural rather than a check somebody remembers to keep.

The other two controls in the design's section 3 are in scope for this task for the same reason: authorization precedes wake, and waking grants nothing.

## Scope

1. **Cursor store.** Durable, one cursor per `(agent, project)`. Advance only after a run reaches a terminal state, in the same transaction as the completion record, so a crash between them re-delivers rather than skips. Delivery is at-least-once per specification section 4.4, so the interface MUST expose event ids for runner-side deduplication. A cursor never moves backward except by an explicit operator action that is itself recorded.

2. **Authorized inbox source, as an interface.** PW1 defines and consumes the interface; the real server-side implementation lands in PW2 and PW3. **The interface MUST return already-authorized results.** Do not provide, and do not leave room for, a variant that returns broad results for the supervisor to filter. Client-side filtering means an unauthorized event already caused a wake, which is the failure this task exists to prevent. Encode that in the type, not in a comment.

3. **Decision loop.** On each tick: read cursor, query the authorized inbox, compute the delta, and decide. Emit `watch.polled` always, `watch.skipped` with a reason when there is nothing to do, `watch.woke` when there is. Cadence configurable per agent, default 240 seconds, with jitter so many agents do not synchronize.

4. **Opt-in and controls.** Off by default per agent. `pause` halts new wakes and lets in-flight runs finish. `stop` halts new wakes and marks in-flight runs for termination; the actual cooperation-free termination lands in PW7, but PW1 must model the state transition and refuse new wakes immediately.

5. **Runner adapter interface, stubbed.** A single method that receives a bounded context package and a scoped token. The stub records invocations so tests can count them. The adapter MUST NOT be able to widen scope, and provider identity confers nothing, per specification section 13.

6. **Events.** `watch.enabled`, `watch.polled`, `watch.skipped`, `watch.woke`, `watch.paused`, `watch.stopped`, with enough structure that an operator can reconstruct why a wake did or did not happen.

Out of scope, and do not build: webhook receipt and signature verification (PW2), real claims, leases and fencing (PW3), real adapters and worktree isolation (PW4), concurrency, retry, dead letter, schedules and budgets (PW5), approval gates (PW6), cooperation-free termination (PW7), metrics (PW8). Do not touch the PostgreSQL migration.

## Tests and acceptance criteria

1. **The zero-invocation control is the headline test.** With an unchanged authorized inbox, a run of many ticks invokes the stub runner **exactly zero times**. Assert zero, not "few" and not "fewer than before". A test that asserts a low count does not prove this property.
2. **An unauthorized event causes no wake.** Given an inbox source whose authorized view excludes an event, adding that event produces `watch.skipped` and zero invocations. Pair it with a positive control where the same event, once authorized, produces exactly one wake.
3. **Waking grants nothing.** Assert the token handed to the runner carries exactly the agent's scopes, with a negative control proving a supervisor holding broader scopes does not widen what the runner receives.
4. **Durable cursor advance.** A cursor advances only on terminal state. Simulate a crash between run completion and cursor advance and prove the work is re-delivered rather than skipped, and that the runner sees the event id needed to deduplicate.
5. **No backward cursor movement** except by the explicit operator path, with a negative control proving an ordinary code path cannot rewind one.
6. **Pause and stop.** Pause blocks new wakes while an in-flight run continues; stop blocks new wakes immediately and marks in-flight work. Negative controls for a wake attempted while paused and while stopped.
7. **Cadence and jitter.** Default is 240 seconds; configuration overrides it; jitter is bounded and does not allow a tick to be skipped entirely.
8. **Determinism.** Same cursor and same inbox yields the same decision. Decisions are a pure function of state, so they can be tested without timing.
9. **Every negative control has a positive control**, and both are reported. A suite that only shows correct refusal does not prove the supervisor ever wakes.
10. Runs from a clean checkout with one documented command, Node only, no new dependency, no network. State the Node version.
11. `npm run proof` and `npm run welcome:test` still pass.
12. Off by default is proven: a freshly configured agent with no explicit opt-in is never woken.
