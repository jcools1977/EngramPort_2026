## Findings, in the order they matter

**1. A dropped phone reply is silent to the phone.** Both workflows share the concurrency group `lex-turn-issues`, and GitHub keeps at most one pending run per group: three comments in a window, or two comments and a push to main, and the middle one is cancelled with no event, no comment, nothing in the log. Separately, `git push origin HEAD:main` throws on a non-fast-forward race or a protection rule, and the script dies before either comment is posted. Either way the person believes they answered.

**2. Directive lines are selected case-insensitively and matched case-sensitively.** A paragraph opening with "Reply: " is selected by `/^reply:/i`, fails the strict match, and the whole comment is refused as malformed. Safe direction, false refusal from ordinary English.

**3. Tag-pinned actions in a workflow that holds `contents: write`.** `actions/checkout@v4` and `actions/setup-node@v4` should be SHA-pinned.

**4. The test stubs are not a fence; they fail open.** Every fixture prepends a stub directory as `${stub}:${PATH}`. On Windows `:` is not a PATH separator and an extensionless node-shebang script cannot execute anyway, so the real command runs. Observed there: the notify suite drove the real PowerShell three times and put balloons on Nick's desktop; the replies suite's `git` stub would have been the real git; its `gh` was ENOENT only because gh is not installed on that machine. The mutation test "identity bypass killed" passed on Windows for the wrong reason: it asserts a refusal, and the observer refuses everything when the harness cannot run. That is the F136 shape.

**5. Three Windows-only harness lines.** (a) The workflow files check out CRLF on Windows (`.github/workflows/` is outside `coordination/.gitattributes`), so the tests' extraction `split('          // BEGIN REPLY LOGIC\n')` finds nothing and the `lex-turns` contract regexes such as `/on:\n  push:/` fail. (b) `symlinkSync(modules, ..., 'dir')` is EPERM without Developer Mode; `'junction'` works. (c) `--import` is handed a bare Windows path, which Node parses as a URL scheme; `pathToFileURL(preload).href` fixes it.
