## The eight corrections

**1. Gate reconciled with task ordering.** Your P0 is right that the fifteen-control gate was unsatisfiable and therefore invited a paper waiver. It is now three tiers with enforceable transitions. **Tier A**, six controls, gates the start of any W3 implementation: authority resolver, atomic bootstrap, plan credential refusal, credential detector, descriptor ingest contract, declared custody models. **Tier B**, nine controls, gates W3 completion and runs entirely on synthetic credentials. **Tier C**, seven controls, gates the introduction of each real credential class at the point that class first exists. The pre-W3 subset is exactly Tier A.

**2. Caller-supplied founder scopes removed as the trust anchor.** Recorded as **F12** and the correction that mattered most. Section 6 now requires an authenticated authority resolver that derives held authority from a trusted store given only the authenticated `principal_id`, with `start` taking no `founder_authority` argument; an atomic bootstrap transaction; resolver output uninfluenceable by the setup payload; and differential controls for a forged assertion and for partial bootstrap failure. What actually holds today is stated exactly: session narrowing relative to an input assertion, absence of a wizard identity in the in-memory manager, and teardown.

**3. Schema replaced with a strict non-invocable descriptor contract.** `input_shape` removed in favour of `shape_ref`, an identifier resolved against a **locally** registered registry, so a provider cannot define the schema it is validated against. `provider_installation_ref` removed; `installation_locator` lives on the grant, so the only field an invocation may read exists because an authorized grant put it there. `invocable: false` is required and constant. `kind` is coupled to its payload branch and each branch forbids the other. Validated with ajv against your three bypasses plus nine more; all rejected, four valid controls accepted.

**4. Inventory expanded from six to eleven.** Added: GitHub webhook secret; key-encryption key and KMS authorization; welcome-package signing key; database runtime credential, distinct from the provisioning credential; and OIDC protocol transients broken out individually, with the note that setup does not request a refresh token because it needs identity, not delegated access. All five of your rows were real.

**5. F9 and F10 marked reproduced; F11 marked confirmed but not exercisable.** F11 is unprevented design scope, not a demonstrated leak, and your point that its closure conflicted with the pre-W3 wording is correct: it now gates Tier C control C4, the first credential-bearing subprocess, not W3.

**6. Custody and signing boundary added as an explicit prerequisite.** New section 9, and you were right that its absence was disqualifying. Six requirements demonstrated with a **synthetic** key before a real one exists anywhere: isolated signing boundary with the application never receiving key bytes; key export disabled with a failing export attempt as evidence; a connector-only identity authorized to sign, with wizard, agents and runners each attempting and failing; KEK controller distinct from all of them; plaintext confinement checked by inspecting logs, error paths, core dumps, backups and process environment during a signing operation; and revocation rendering existing ciphertext unusable immediately.

**7. Language audited.** Every protection now carries **[IMPLEMENTED]**, **[TEST-GATED]**, or **[FUTURE]**, with a leading note that nothing is enforced because it is written here. Your P1 corrections are all reflected: founder non-retention is narrowed to the session object and says nothing about OIDC state outside that interface; temporary agent credentials are narrowed to scope separation, since there is no token value, minting, expiry, or revocation; section 8 is narrowed to in-memory teardown, since W1-1 creates no external effects.

**8. Custody models split.** You caught the contradiction between "EngramPort is not a secret manager" and "EngramPort stores the App key encrypted". Section 5 now defines three models: participant-owned external reference, tenant-owned ciphertext under external custody where the KEK holder is not the wizard, and operation-scoped fetched token. Leakage now covers CI logs and caches, Git object database and reflog, backups and snapshots, core dumps, shell history and editor state, with the note that quarantine is not safety unless the quarantine is itself a narrower secret store, and that rotation is the only reliable remediation for any sink.

## A finding against my own revision

My first pass at the new schema constrained `credential_ref.locator` to the shared `identifier` grammar, which permits dots because capability names need them. A JWT is dot-separated base64url, so **a JWT passed validation as a locator**. My own probe caught it; rereading the schema would not have. The locator now has a tighter grammar with dots excluded.

I am recording that in the manifest rather than quietly fixing it, because your critique was right, my first fix was still incomplete, and the difference between the two was testing rather than rereading. That is the same standard I have been holding your work to.
