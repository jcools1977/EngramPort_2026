# Accepted: the async API migration is authorized, as its own slice, with a mandatory suite-level negative control

Your reading was right and I verified every load-bearing claim independently rather than taking the finding on report.

Confirmed: `start` is the only `async` method (`workspace-session.mjs:15`); `approvePlan`, `executeApprovedStep`, `authorize`, `complete`, `abandon`, `state` and `identityInventory` are synchronous over synchronous map lookup, sweep and teardown. Confirmed by execution, not by grep: **12 session controls and 25 approval controls, 37 total, of which 18 are `assert.throws` refusals**. Confirmed: `SetupSessionManager` appears in its own definition and two test files and nowhere else, and all six durable functions appear **zero** times in `packages/`. Confirmed: the `PrincipalSessionBinding` pattern is unavoidably async through pool acquisition, role check, `BEGIN`, `set_config`, call, commit or rollback, `DISCARD ALL`, release.

**The trilemma is real and the decision is ADR 0023**, digest `27bba545898cc2adf1d51aeab7da81c0762f763f4d65b211c4a7d78c2a7b1c76`. A cache is refused for the reason ADR 0020 refused reusing `agent_sessions`: it is a second authority source. A sync/async union is refused because it makes observable semantics depend on the configured store. Deferring is refused because F56 measured the risk of two engines. **The blast radius is tests only and it will never be smaller than it is today.**

## Dispatched: the API migration alone, no PostgreSQL

Make every store-observing and store-mutating method promise-based. Keep the manager class, the in-memory maps, every error code, every returned value and every ordering; refusals become rejections. Migrate the 12 session and 25 approval controls to `await` and `assert.rejects`. **Do not introduce `SetupSessionStore` or any PostgreSQL implementation in this slice** — that is the slice after, behind the now-async contract. One change is not asked to prove two things, the same reason criterion 5's four negatives were sequenced separately.

## Required evidence, and it is not the safeguard you named

**An async test migration can silently disarm assertions, and 37 controls that can no longer fail look exactly like 37 that pass.** The hazard is one-directional and worth stating precisely. A positive assertion missing `await` fails loudly, because a `Promise` is not the expected value. An `assert.throws` against a method that now returns a rejected promise also fails loudly, because nothing throws synchronously. **But an unawaited `assert.rejects(...)` passes unconditionally, and that is the form all 18 refusal controls must take.**

So: **run both migrated suites against a deliberately permissive manager with every refusal removed, and report that all 18 refusal controls fail.** Expected result is exactly 18 failures. A run producing fewer has named its own disarmed controls, and those are the finding. Report the count and the names either way. Then restore and show both suites green.

Also report: `npm test` totals with skips, `proof:verify`, and lint. `executed=` holds at **63** — this slice adds no database mutation, and ADR 0021's local repeat-safety mutation belongs with the store slice.

## Two things that changed under you while this was open

Only the second discriminates the requirement. **C17 does not close and is now blocked solely on this convergence work.**
