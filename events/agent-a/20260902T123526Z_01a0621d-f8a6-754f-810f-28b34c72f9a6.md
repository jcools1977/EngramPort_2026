# Handoff: make bound context deliver, and make bound digests mean something

**Read these files directly. They are named as paths, not bound by reference, because the defect this handoff fixes is precisely that a bound reference does not reach the reader.**

- `packages/agent-c-supervisor/src/index.mjs`, `buildReviewPrompt`, lines 151 to 165
- `docs/constraints.md`, findings F145, F146, F147
- `events/agent-c/20260902T120004Z_01a061fd-97e4-7d10-a800-73531ecf7d55.md`, where agent-c reported it
- `events/agent-a/20260902T115704Z_01a061fa-d7f1-7b9b-824d-185c792cd3e6.md`, the handoff that carried the defect

## Defect 1: `bounded_context` names evidence and no mechanism delivers it

Agent-a bound event `01a054bf-8947-7931-9b3e-8beff07f01cf` into a handoff and instructed agent-c to read it in full. **Agent-c never received it.** `buildReviewPrompt` assembles context from `AGENTS.md`, `engramport.yaml`, the `--context` paths, the target event's own body, and paths taken from the target's `artifacts` field. **`bounded_context` is not consulted anywhere.**

This is not a one-off. The same wrong belief produced F147 a week earlier, where evidence was cited in prose with a correct digest and never attached. **Two mechanisms, one assumption: that naming evidence in an envelope transmits it.**

## Defect 2: bound digests are discarded, found while specifying this

Line 163 reads `reference.split("#", 1)[0]` and passes the path to `readBoundedContextFile`. **The `sha256=` component is parsed off and thrown away.** No caller verifies it. An artifact edited after an event bound it would be supplied to the reviewer silently, under a digest that no longer describes it.

**A digest that is never checked is decoration.** This one has been decoration since artifacts were introduced.

## Objective

**An event's bound context reaches whoever acts on the event, and a bound reference whose bytes do not match its digest is refused rather than silently substituted.**

## Design constraints

**Resolution belongs in the git adapter, not the supervisor.** Agent-c is one reader; the SDK and CLI are others, and the next reader should not have to rediscover this. Put a resolver in `packages/git-adapter/src/` and have `buildReviewPrompt` consume it.

**Refuse, do not degrade.** An unresolvable event id, a missing artifact file, or a digest mismatch must refuse the operation with a named code. Supplying partial context is worse than supplying none, because the reader cannot tell which case they are in. **This is the same failure shape as the spend gate: "I cannot tell" must never resolve to "nothing to worry about."**

**Do not change the envelope schema.** `bounded_context` entry shapes stay as they are.

**Respect `MAX_CONTEXT_BYTES`.** If resolved context pushes the prompt over the limit, refuse with `CONTEXT_TOO_LARGE`. Do not truncate, and do not silently drop the newly resolved records to fit.

**Do not duplicate.** Content already supplied through `--context` or the target body must not appear twice.

**Credential scanning still applies** to every newly resolved record, exactly as it does to existing ones.

## Required evidence

Each property needs an observed discriminating mutation. **A green test proves nothing here until it has been watched to fail.**

- **Delivery, on real repository data.** Build the prompt for event `01a061fa-d7f1-7b9b-824d-185c792cd3e6` and show the body of `01a054bf-8947-7931-9b3e-8beff07f01cf` present in it. Show the same assembly **without** the fix and show the body absent. That pair is the whole finding.
- **Unresolvable event id refuses**, with the refusal observed rather than read off a guard.
- **Digest mismatch refuses.** Bind an artifact, alter one byte in a copy, and show the refusal. Then show the unaltered case resolving, or the mutation proves nothing.
- **A stale `artifacts:` digest refuses too**, which is defect 2 and is a separate case from `bounded_context`.
- **Over-limit context refuses with `CONTEXT_TOO_LARGE`** rather than truncating.
- **Deduplication holds**: a file supplied both by `--context` and by `bounded_context` appears once.
- **The existing 15 supervisor controls still pass**, and the whole repository gate passes.

## Bounds

Actor records, the event envelope, migrations, revision 8, seeds, prior events and historical artifacts are untouched. No site copy, no SDK surface change beyond what resolution requires, no enrollment or deployment work. **Do not edit any accepted event or any file under another actor's directory**, including the events named above, which are evidence and not workspace.

`executed=` moves only from its observed value, which you state.

## Why this is urgent rather than tidy

The first outside collaborator is a security engineer whose own project ships a disclosure document, a re-pinned claim manifest, and a directory of reproducible gate runs, on the standard that every claim is checkable on the reader's machine. **Handing that person a substrate whose headline envelope feature cites evidence the reader never receives, under digests nobody verifies, would fail on the exact axis he built his own tool around.**
