# Pre-flight: the durable cursor implementation

**Council 03 settled this design and DeVere funded the build.** Both voters converged independently; you audited the existing package and rejected its claim with ten findings, all of which this dispatch must answer.

---

## PROPOSED DISPATCH (not yet sent)

**Objective: make *"Port Watch delivers new work through durable cursors"* true.**

**Position is derived from the log, never stored.** No cursor number exists to advance, which removes the `rewind` defect structurally rather than guarding it. Durability comes from the log: a fresh clone reproduces the same answer, and two builders cannot diverge because there is nothing to diverge.

**A cache is permitted and must be disposable**, keyed to log state. **Deleting it must cost time and never correctness**, which is the projection property `port-family.md` requires: *"no projection may become truth by being useful."*

**Two delivery classes:**

1. **Work deliveries**: addressed, unanswered, authorized. **Shares one eligibility resolver with `listInbox`** rather than a second implementation that agrees today.
2. **Observation deliveries**: authorized thread or causal subscriptions, produced even when another actor holds the turn, so an artifact, reply or completion can reach a subscriber. **These grant no turn, claim, approval or implementation authority.**

Both carry stable delivery ids and durable dispositions.

**Delivery must deliver.** You found that `decideDelivery` returns wake or skip, and `tick` decides and optionally invokes an injected runner while appending nothing and making nothing discoverable. **The site promises a behavior**, so the delivered payload must carry the work and delivery must be observable after the fact.

**Scope of "new work" is not one handoff.** `decideWatch` keeps only the first `handoff` carrying `implementation_authority`, so replies, artifacts and completions are never delivered. The claim says new work.

**Required evidence.** A discriminating mutation per property, plus:

- **The cache is disposable:** delete it and prove the delivery set is identical, only slower.
- **A fresh clone reproduces the same set**, which is the F115 defect that started this.
- **Two concurrent processes do not diverge**, replacing `FileWatchStore`'s single-writer assumption.
- **Observation deliveries confer nothing:** attempt to claim a turn from one and **observe the refusal**, not the guard.
- **One resolver:** mutate it and prove both the watcher and `listInbox` change together.

**Migration:** say what happens to existing local watch state.

**Bounds.** Port Watch and the shared resolver. No SDK, no new event type, no envelope change, no enrollment. `executed=` moves from **129**.
