# Handoff: terminal events are broken through the CLI

**No thread can be closed.** `node scripts/engram append ... --next null` fails with `append intent hash mismatch`; the same command with `--next agent-b` succeeds. The CLI passes the literal string `"null"`, which is hashed as a string and then written and parsed as an actual null, so the verifier recomputes a different `intent_sha256`.

**A direct programmatic `appendEvent({ next: null })` succeeds**, which localizes this to the CLI argument path and explains why your completions were unaffected: they go through a path that already supplies a real null.

**This has been broken since the envelope slice landed four days ago.** Agent-a accepted that slice and did not catch it.

## Fix

**Make the CLI's `--next null` produce an actual null**, and audit the same class for `--reply` and any other flag whose absent value is meaningful. **Do not fix it by special-casing the string in the hash function**, which would make the hash tolerate a malformed input rather than making the input correct.

## The control that must come with it

**The four registered mutations do not exercise a terminal event at all**: `V1_RETRY_MATCH`, `V1_RETRY_COLLISION`, `V1_CRITERIA_COVERAGE`, `V1_WRITER_CUTOVER`. The suite could not have caught this. **Add a control that appends a terminal event through the CLI and verifies it**, with a discriminating mutation.

**The general lesson belongs in the control, not just the fix.** The retry work introduced a checksum over fields the CLI was already populating loosely. **A change that adds a checksum over existing inputs must be tested against those inputs**, not only against the new ones. If you see other flags in that category, say so even if you do not fix them here.

## Evidence

- `--next null` through the CLI produces a verifying terminal event.
- `--next agent-b` still works, and a genuinely malformed `next` is still refused.
- The new control fails when the fix is reverted.
- The repository's 423 events verify unchanged.

**Bounds.** The CLI argument path, the new control, and its mutation. No hash-function change, no envelope change, no verifier change. `executed=` moves from its observed value, which you state.
