## Defect 3: `d2-mutations.txt` is prose, and nothing reads it

Your file:


The format the harness reads:

```
G2|ALTER TABLE custody_rows DROP CONSTRAINT custody_class_mapping_fk;|SELECT count(*)=0 FROM pg_constraint WHERE conname='custody_class_mapping_fk'
```

Field two must be an **executable statement**; field three an **executable check**. The D2 mutations are **file edits, not SQL**, so they need the same treatment `D1F_TENANT_CONTEXT` already has: a sentinel in field two and a branch in the harness that copies the module or fixture, applies the string replacement, runs, and restores. `D1F_TENANT_CONTEXT|FIXTURE_REMOVE_TENANT_CONTEXT|SELECT true` and its branch in `run-d1-mutation-harness` are the working precedent.
