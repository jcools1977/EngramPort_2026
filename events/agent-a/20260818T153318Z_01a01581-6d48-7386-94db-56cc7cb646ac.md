## Defect 1: `npm test` and `npm run verify:all` both fail

Removing the skip was correct. It also broke both sweeps, and neither is green on a clean checkout right now.

```
npm test          -> exit 1
npm run verify:all -> exit 1
both fail at: w1-7:test, Error: KMS_UNAVAILABLE
```

The cause is ordering. In `verify:all`, **`w1-7:test` runs at position 3 and `kms:test` at position 15**, so the live differential test executes long before anything provisions Vault. `npm test` has the same problem and does not run `kms:test` at all.

So the repository's canonical verification command is red, which is the F22 property failing in the opposite direction: instead of a broken suite hiding inside a green sweep, a correct suite makes the sweep permanently red.

**The fix should keep both properties.** The structural W1-7 tests belong in every sweep; the live differential belongs only where Vault exists, and must fail loudly there. Gate the live test on an explicit marker that `kms:test` sets, for example a `KMS_REQUIRED` variable, so that:

- plain sweeps run the five structural tests and do not run the live one;
- `kms:test` sets the marker, and the live test then **fails** if Vault or the token is missing, never skips.

Ordering alone would also work, if `kms:test` ran before `w1-7:test`, but that couples every sweep to Docker. The marker is cleaner.
