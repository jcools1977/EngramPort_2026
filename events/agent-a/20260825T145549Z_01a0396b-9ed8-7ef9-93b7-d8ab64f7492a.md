# Objective: cost the runtime that can own OIDC transaction continuity. A reading, not a choice

DeVere holds this decision. **Reading only** — no implementation, no provider, no credential, no network, no Cloudflare API call. `executed=` stays at **91**. Nothing closes.

## What is now established

F81 records the verified facts: `engramport.com` is served through Cloudflare, the application builds to a **Cloudflare Worker** via `wrangler`, `@cloudflare/vite-plugin` and `vinext`, and the generated `dist/server/wrangler.json` declares **`durable_objects.bindings: []`, `kv_namespaces: []` and `secrets_store_secrets: []`** — no state bindings at all. `dist/` is gitignored, so that config is generated at build time.

Your F79 blocker therefore has a concrete shape: `createOidcClient` holds transactions in a module-scope `Map`, and **Workers are isolates with no request affinity**, so `state`, `nonce` and the PKCE verifier will not reliably survive auth-start to callback. **It fails intermittently rather than cleanly**, which is the worse failure — it reads as a flaky provider rather than a design fault.

## Cost these, and add any I have missed

**A. Durable Objects** — one object keyed by `state`.
**B. Workers KV with a short TTL.**
**C. Off-Workers long-running process**, leaving `engramport.com` as it is.
**D. Anything else**, including options that avoid the question rather than answering it.

For each, return:

1. **Does it actually preserve continuity?** Prove or refute against the real Workers execution model rather than the marketing description. **If an option only *usually* works, say so** — an intermittent OIDC failure is indistinguishable from a provider outage and will be debugged in the wrong place for a long time.
2. **What retention boundary does it create?** Specifically whether the **PKCE verifier and nonce are persisted**, where, for how long, and who can read them. **This is the discriminating question**, because F79 established that persisting them introduces a new credential-retention boundary that the current design does not have. **An option that keeps them non-persistent is categorically different from one that does not**, and should be costed as such rather than on convenience.
3. **How the client secret reaches token exchange**, measured against ADR 0031 and *no secrets on disk*. F81 records that a Worker has no process start and cannot invoke `op`, so deploy-time injection is the reconciliation — **cost that honestly, including who performs it and how rotation works.**
4. **What accepted surface changes**, with file and line.
5. **What new controls are required, and how much is synthetic-provable locally.** `wrangler` can run Workers, Durable Objects and KV locally. **Say plainly which properties a local run can actually establish and which it only simulates** — a local emulation of an isolate model is not evidence about production isolate behaviour, and claiming otherwise would be the fake-scheduler pattern in a new costume.
6. **Operational obligations**: availability, recovery, patching, and what happens to an in-flight authorization when the runtime restarts or an object migrates.
