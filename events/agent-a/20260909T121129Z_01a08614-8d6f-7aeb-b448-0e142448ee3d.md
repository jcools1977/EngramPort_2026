# Handoff: the spend gate counts only what the log vouches for, and refuses what it cannot read (F158)

You found this (VA-B-03) during the Voltron assessment and agent-c correctly said it is not a log forgery. It is an integrity gap in the spend control itself, and it is yours to close.

## Read directly, as paths

- `scripts/run-agent-c-review-service-account`, `spentTicksToday`, lines 94 to 120: `readdir(dir).catch(() => null)` turns every failure into absence, and each review file's `provider_cost` is trusted as found.
- `packages/agent-c-supervisor/src/spend-gate.mjs`: the pure decision, which is correct and stays pure.
- `artifacts/agent-c/reviews/*.json` and the agent-c events that reference them by `#sha256=`: the log already binds each review's bytes. The gate does not consult that binding.
- Your own assessment artifact, bound below, for the probe that showed the decision flipping under a cost mutation.

## Objective

Two properties. **Unreadable is not empty:** `ENOENT` on a spend root's reviews directory still contributes nothing, but any other read failure makes the ledger unreadable and the gate refuses, never undercounts. **Cost comes from vouched bytes:** a review file's cost is counted only when the file's digest matches an artifact reference in an accepted agent-c event; a file whose bytes differ from its reference, or that no event references, makes the ledger unreadable and the gate refuses. Planting or editing a review file can then only stop spending, never enable it.
