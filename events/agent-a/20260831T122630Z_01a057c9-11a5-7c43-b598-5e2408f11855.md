# Handoff: sign your commits

**DeVere generated and registered signing keys for both committing actors.** `~/.ssh/engramport_agent_b` is yours; its public half is registered with GitHub as a signing key. Agent-a is already signing: commit `64885c2` verifies as `G`, signed by `agent-a@engramport.local`.

## Build

**Sign your commits with your own key, per-command**, alongside the identity you already set:

```
git -c user.name="agent-b (Codex Builder)" -c user.email="agent-b@engramport.local" \
    -c gpg.format=ssh -c user.signingkey=~/.ssh/engramport_agent_b.pub \
    -c commit.gpgsign=true commit ...
```

**Do not set `commit.gpgsign`, `gpg.format` or `user.signingkey` in repository or global config.** DeVere commits from this machine and would inherit whichever key is configured, which defeats the distinction the keys exist to create.

**The verification mapping is deliberately not in the repository.** It lives at `~/.ssh/engramport_allowed_signers`. **Do not add a key field to `actors/*.yaml`.** F128 established that an in-tree actor-to-key binding is rewritable by any actor who can commit, together with whatever check would have caught the edit, so an in-tree binding would look like progress and change nothing.

## Evidence

- A commit you author verifies as `G` signed by `agent-b@engramport.local`, shown with `gpg.ssh.allowedSignersFile` pointed at the file above.
- **Repository and global `commit.gpgsign`, `gpg.format` and `user.signingkey` are unset afterward**, proven by reading them, so DeVere's commits are unaffected.
- **State plainly that signing still does not prevent impersonation.** Anyone who can read a key file on this machine can sign as its owner, and all keys live on one machine. The fix is the verifier comparison, not the signature.

## What comes next, so you can see where this leads

Once both actors sign, DeVice enables required signatures on `main`, and then **the verifier compares an event's claimed `from:` against the signer of the commit that introduced it.** That is the step that turns F127's `impersonation=accepted` into a refusal. **This slice is a prerequisite for it and is not it.**

**Bounds.** Your own commit signing and a note in the result. No config mutation, no `actors/*.yaml` change, no verifier change, no branch protection. `executed=` does not move.
