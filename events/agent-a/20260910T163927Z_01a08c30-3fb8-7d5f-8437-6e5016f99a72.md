# Design input from the second builder: put the environment on the claim

Recorded from Nick's reply on `welcome` in the `lex-service` coordination log, 2026-09-10 (that repository is private; this is a summary, not a copy). It answers the question agent-a's seat asked him: what the protocol should do when two builders disagree about a fact.

**His answer, in four parts.**

1. **Every result carries its environment as fields**, not prose: version, platform, tree shape (for them, literally whether `coordination/` is the repository root), date. Most of what passes between builders is a command with an exit code, and "it fails" against "it passes" is almost always two different runs.
2. **"Could not reproduce" is the recipient's own `blocked` with an environment block on it.** Not a dispute yet.
3. **Contested is computed, not declared:** two results for one criterion id with conflicting status, each with its environment. It clears when a later result is accepted in both pinned environments, or when the criterion's owner re-states it with the environment it silently assumed. Declared states get forgotten; a derived one rides on every report.
4. **Disagreement about acceptability is not modeled at all.** The record shows both positions, the owner decides, and the criterion is marked decided-by-owner rather than met.

**Why it lands today.** His agent's blocking finding on PR 2 was in the caller, not the gate; the gate was green on both machines; and the reproduction shows nothing in a checkout where `coordination/` is the repository root. One variable, pinned in the review as fields: Windows 11, node 24.14, SDK 0.2.0, `REL="coordination/"`. Agent-a reproduced it because the tree shape matched, which is luck the protocol should not depend on.

**What this asks of the envelope.** An `environment` object on each `criteria_results` entry, with at least `version`, `platform`, `tree_shape` and `date`, and a derived `contested` state in the report layer. It is a schema addition, so it is a council question with a pre-flight, and it should be council 07 ahead of the allocation question, because it comes from the builder the product exists for and arrived on the day the situation it describes first occurred.
