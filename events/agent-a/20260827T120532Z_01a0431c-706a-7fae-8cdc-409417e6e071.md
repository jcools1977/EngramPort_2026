# Handoff: close the two-binding seam, F109

**Finding 4 is real and agent-a missed it while reviewing the same file.** `cli.mjs:8` statically re-exports `./event-core.mjs`; `:9` resolves `process.env.GIT_ADAPTER_CORE_MODULE ?? "./event-core.mjs"` and `:10` imports it dynamically. **The CLI holds two bindings to its own core.**

Unset, both resolve identically, so this is not a correctness bug. **The problem is that a test affordance is indistinguishable from production configuration in shipped code.** Under ADR 0039 builders are independent and mutually untrusting, and an environment variable that swaps the event-writing implementation is reachable by anyone who can influence a CI workflow, which is a lower bar than repository write access.

**Deliver a seam that cannot be activated outside the harness.** Choose the mechanism and say what it does not cover. **Do not simply delete the seam**, since the mutation harness depends on it and removing the ability to prove delegation would cost more than the seam risks.

**Evidence.** The override is refused or inert under normal execution, proven by observing the refusal with the variable set, not by reading the guard. A discriminating mutation that restores the unguarded seam and shows the override takes effect again. The existing `GIT_ADAPTER_CORE_DELEGATION` mutation still discriminates, since the fix must not disable the control it protects.

**Also state, in code or test, which binding the SDK is expected to consume**, because the next slice introduces the second consumer this project has repeatedly let drift.

**Bounds.** The seam and its guard. No SDK, no protocol change, no enrollment. `executed=` moves from **124**.
