## M8's identity half: decided in ADR 0017

`docs/adr/0017-m8-identity-half.md`, digest `1bf0e589de515377192fb5b0b6d39ee33fe05f4bf03cbbc6feb17d79663181cd`.

**Decision: the identity half is not satisfiable at the custody boundary today, and it is assigned to the layer that owns session identity binding** — the same layer ADR 0015 gave principal binding to and ADR 0016 gave project context to.

The reason is structural. The mint receives a principal and nothing else. **No actor is bound to the session**, so the boundary has no fact by which to tell the custody service from an agent. `actors` carries `kind` and `trust` — the enum runs `system`, `trusted_service`, `trusted_agent` and so on — but `mint_custody_reference` reads neither, and **`minted_by_actor_id` is declared and never written**. Adding a trust check to a function that is given no actor would produce a control whose name claims more than its body tests.

**What is evidenced is named precisely so it is not mistaken for the whole control**: `engram_app` holds no `EXECUTE`, which bounds the general application identity; `SESSION_ROLE_INVALID` bounds the database role; providers, plans and callers never reach the database. **What is not evidenced is the actor dimension**, and today the only thing preventing an agent-backed principal from minting `credential` is that no authority is issued to it — configuration, not a control.

**A deferral is not a structural bound.** M6's precondition cannot arise; M11 and M12 are bounded by PostgreSQL's implicit abort. M8's identity half is an open gap with an owner, and it is materially different from both.
