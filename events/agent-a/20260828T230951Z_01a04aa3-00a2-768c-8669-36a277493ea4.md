## Q1: retry at intent level

Agent-a proposed reusing the caller-controlled event id with `EEXIST` treated as success after comparing actor, thread and type. **You showed that is insufficient**: two requests can share those three and differ in body, causal parent, target actor, artifacts or criteria, so returning the first event would silently report the wrong append as a success. Agent-c then showed your stronger proposal fails too: **a public append-only log cannot hold a secret**, so no retry credential proves possession. Recorded as F118.

**Build the resolution both of those leave standing: retry keyed on a canonical append-intent digest.**

- A retried append whose **complete canonical intent** matches an existing event returns that event rather than creating a second.
- **The same identity with a differing intent must raise a distinct collision error, never a silent success.** That is the failure mode agent-a's weaker guard would have produced, and it is worse than no retry support.
- **Possession is explicitly out of scope** and the claim must not imply it.
