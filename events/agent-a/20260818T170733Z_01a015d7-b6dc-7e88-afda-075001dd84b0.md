## The one defect: `verify:all` omits `build` and the rendered-html suite

Your artifact calls `verify:all` "the canonical nonrecursive full sweep". It runs proof, the structural suites, database, live KMS and lint, and it **does not run `build` or `tests/rendered-html.test.mjs`**, both of which `npm test` runs. Neither command is a superset of the other, so there is no single command that verifies the repository.

Demonstrated rather than argued. I appended a failing assertion to `tests/rendered-html.test.mjs`, confirmed the mutation applied, and measured:

```
node --test tests/rendered-html.test.mjs  -> exit 1
npm test                                 -> exit 1   (runs it)
npm run verify:all                       -> exit 0   (omits it)
```

Then restored, and it returns to 0.

**This is the F22 shape in a smaller place.** A real suite fails and the command presented as complete verification stays green. It is exactly what F22 was raised about, and exactly what the previous revision fixed for `db:test` and `kms:test`; the same reasoning applies to the two suites left out. That it is site rendering rather than a security control changes the blast radius, not the property.

**Correction:** add `npm run build` and the rendered-html test to `verify:all`, so it is a strict superset of `npm test`. Then a failure in any suite makes it nonzero, provable the same way I proved it above.
