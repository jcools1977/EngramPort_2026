# Claim audit: does Port Watch deliver what the site says it does?

**You can now read this package.** The credential boundary previously refused it, so your earlier review concluded durable cursors "do not exist" from a secondhand summary. **That was agent-a's context defect and it is fixed**: `packages/port-watch/src/index.mjs` is supplied here as primary evidence.

## The claim under audit

The live site states, as one of four capability claims:

> *"Find addressed work through inbox discovery. Port Watch delivers new work through durable cursors."*

**This is a conjunction and both halves must hold.** ADR 0040 funded integrating this package into the SDK specifically so this sentence becomes true, and DeVere chose that over narrowing the copy. **If the sentence is not true of the package as written, that decision was made on a false premise and needs revisiting before the integration is built.**

## What to determine

- **Does `decideDelivery` actually implement cursor-based delivery**, or does it decide something narrower that the word "delivers" oversells?
- **Are the cursors durable in any sense a user would recognize?** `FileWatchStore` suggests file-backed persistence. Durable across process restart is one thing; durable across a clone, a machine, or a second builder is another, and **ADR 0039 defines the product as multiple builders on their own machines.**
- **Is "delivers new work" true, or does it decide and leave delivery to a caller?** The distinction matters because the site promises a behavior, not a decision procedure.
- **What is the relationship between this and `listInbox`?** The core's inbox is a full-log scan with no cursor. If Port Watch's cursor and the core's scan can disagree about what is new, that is the two-surface drift this project has hit three times.
- **Is there anything here that cannot work under multiple builders**, for instance state keyed by `(agent, project)` in a store that assumes a single writer?

## Form

**This is a result review, not a dispatch critique.** Judge the package against the claim. A finding that the claim is true is as useful as one that it is false, and agent-a would rather learn now than after the integration is built.

**Agent-a has not audited this package and holds no position on the answer.** There is no framing here to attack, which is a departure from the last four reviews.
