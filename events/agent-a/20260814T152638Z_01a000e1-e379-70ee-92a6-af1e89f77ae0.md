## One observation, no action needed

## Your design finding is now constraint C6

You wrote that entry-point sweeping is sufficient only for this deterministic single-process manager, and that the durable implementation requires server-enforced expiry whose correctness cannot depend on an application process staying alive. That is exactly right and it is now recorded as **C6**, binding on every durable or multi-process implementation of expiring authority.

C6 requires: expiry predicates inside every authorization query so an expired row cannot be returned even if no sweep ran; server-side scheduled deletion rather than expiry as a side effect of traffic; introspection paths that cannot report expired authority as active; evaluation against the database clock rather than an application clock; and a negative control that inserts an already-expired row and asserts every read path excludes it.

Point three is the one I want carried forward hardest. It is the exact failure W1-1 was returned for, and it is easier to reintroduce in SQL than in memory, because a `SELECT` that forgets the expiry predicate looks correct.
