## The six

**B1, custody mint.** Section 5A and control **A8**. The caller supplies no reference id, UUID, namespace binding, tenant, project, principal, or actor; every one is derived. Minting authority is per namespace: shape to the registry path, installation to the installation path, credential to the custody service, with providers, plans, callers, agents, runners and the general application identity never permitted. Nine steps in one transaction committing both or neither. Thirteen negatives and a positive, covering cross-tenant, cross-project, expired and revoked grant, revoked custody row, excessive scope, duplicate UUID, concurrent race, and two rollback faults proving neither an orphan row nor an orphan reference survives.

Your orphan point is why M11 and M12 exist. The schema correctly accepts a syntactically valid but unresolvable reference, because structure cannot prove resolution; the custody API is what must guarantee a valid-looking reference either resolves or was never minted.

**B2, shape selection.** Taken out of provider control entirely. The wire descriptor carries `provider`, `capability`, `protocol_version` and **no `shape_ref`**. Ingest derives the pinned shape revision from the trusted integration binding, and provider bytes are validated **against** the selected schema rather than selecting which valid schema applies. Control **A9** refuses a wire descriptor carrying `shape_ref` and refuses a mismatch. The stored descriptor records `shape_revision` so a later registry change cannot retroactively reinterpret a stored record.

You were also right that "no reference of any kind" was literally false. The text now says no custody or authority-bearing reference, which is what was meant.

**B3, resolution.** Twelve comparisons rather than a property, since "authorized consumer only" names a conclusion and not a check. Invoking principal equals `granted_to_principal_id`; invoking actor equals `granted_to_actor_id` where present; tenant and project equality; requested scopes contained in stored scopes with a superset refused rather than narrowed; provider and capability equality; unexpired against the database clock; grant not revoked, re-read within the invocation rather than cached; setup session not revoked; and referenced custody rows not revoked at use time. Fourteen negatives and a positive. "Existence of a valid reference or a live custody row never suffices" is now in the document.

**B4, mechanical transitions.** W1-5 through W1-7 must be registered before Tier A dispatch, and I have not registered them, because that is a change to the task plan rather than to W1-2. An evidence registry keys every control to the **exact revision** it was demonstrated against, so adding a control invalidates a prior all-clear. W3-1 dispatch fails closed unless every Tier A control passed for the current revision, enforced by dispatcher, CI or task state, with a test proving that removing a passing entry makes dispatch fail. **While C1 blocks any applicable Tier A control, W3-1 is mechanically ineligible** and no waiver may override it. Your line that C1 is honest only if a missing host blocks progress rather than authorizing a waiver is now the operative rule.

**B5, lifecycles.** Sixteen rows. Added the **App authentication JWT**, distinct from the installation access token, with issuer, claims, a ten-minute ceiling, single use, the fact that no independent revocation exists, and destruction at exchange. Added back **setup-session delegation authority**, which revision 2 had and revision 3 dropped, distinct from the temporary agent credential: one authorizes a runner, the other authorizes the session. New gates C16 and C17. The 3.13 defect is fixed by placing the model provider token explicitly outside setup, owned by runtime configuration, rather than leaving a FUTURE row with no owner.

**B6, canary.** Every sink runs twice. An isolated **vulnerable variant** routes the known canary into that sink and the observer must detect it; only then does the protected variant run and prove the sink clean while signing still succeeds. A sink never observed dirty is a sink whose observer is unproven, which is exactly your point about trace logging and argv reads. The canary import path is structurally isolated from the production non-exportable-key path.
