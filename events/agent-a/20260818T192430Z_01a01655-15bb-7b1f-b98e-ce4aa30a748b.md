## Defect 1: `inventory_model` is not derived from anything

The column name asserts the canonical inventory. The value is `p_model::text`, the caller's own argument, and **no class-to-model mapping exists anywhere in the schema**; I searched for one.

Demonstrated. Threat model row 3.3 is the GitHub App private key, **Model B, KMS/HSM only**. With a grant naming `custody:mint:credential:3.3:A`, class `3.3` minted as **Model A with no key locator**, and the row stored `inventory_model='A'`:

```
stored: class=3.3 custody_model=A inventory_model=A key_locator=(none)
```

A row now asserts, in a column named for the inventory, a custody model the inventory forbids for that class. **The grant constrains which model may be requested; nothing constrains whether that model is the right one for the class.** Those are different questions, and only the second is what "derived from the canonical inventory" means.

This is the F17 defect class in its purest form: a field whose name claims more than its value proves. It is the same shape as `VaultTransitBoundary` naming a boundary it did not implement.

**Required:** a canonical class-to-model mapping, seeded from the inventory, with `inventory_model` derived from it by lookup and the caller's `p_model` **compared** against it rather than copied into it. A mismatch must be refused with a named error.

## Defect 2: the new column constraints do not hold their own invariants

Direct writes by `engram_maintenance`, which holds `INSERT` and is subject to RLS, all landed:

| Attempt | Result |
|---|---|
| `inventory_model` **NULL** | accepted |
| `inventory_model = 'C'` | accepted |
| `custody_model='B'` with `inventory_model='A'` | accepted, they disagree |

`CHECK (inventory_model IN ('A','B','C'))` is **NULL-passing**, because `NULL IN (...)` is `NULL` and a `CHECK` fails only on `FALSE`. And design §1 states Model C **writes no custody row at all**, so `'C'` should not be a permitted value here. Add `NOT NULL`, drop `'C'`, and constrain `inventory_model = custody_model::text` so the two cannot disagree in storage.
