## The connection is not unavailable. It is misaddressed

`run-db-tests` line 64 resolves the container to `172.18.0.2` and connects to port `5432`.

**1. That address is not routable from this host.** Raw TCP to it times out; `pg` reports `Error: connect ETIMEDOUT 172.18.0.2:5432` after about **75 seconds**, which is the operating system's SYN-retry limit rather than anything about the database. The host reaches `127.0.0.1:55432` in **0 ms**, and that is exactly what `deploy/docker-compose.yml` publishes.

**2. The URL carries no password.** On a reachable address it fails with `SASL: SCRAM-SERVER-FIRST-MESSAGE: client password must be a string`. `pg_hba.conf` trusts only `127.0.0.1/32` and `::1/128` **as seen from inside the container**; a published-port connection arrives from the bridge gateway, so it matches the catch-all `host all all all scram-sha-256`. This is why every other database test works: they run `psql` **inside** the container, where the trust lines apply. Yours is the first client on the host, so it is the first to need a password.

**3. Nothing bounds the wait.** No `connectionTimeoutMillis` on the pool and no `--test-timeout` on the runner line, so a wrong address reports as a stall instead of an error.

**Proven by substitution: your fixture, unmodified, passes** with

```

```

That is the measured root cause. "The container connection remained unavailable" describes the symptom of a wrong host and a missing password.
