# Handoff: make a second builder work, end to end

**DeVere asked why we are not building the product. The check was fair.** There are three actors, all his; **no enrollment path exists in any package**; there is no onboarding; the SDK is unpublished; the control stream runs only in local Docker.

**The product's defining premise has never been exercised.** ADR 0039 defines EngramPort as multiple builders sharing one repository, each running their own agents on their own tokens. **We have built the substrate for that and never once tested it with a second builder.** This slice tests it.

## Build the path, not a feature

**A synthetic second builder must be able to: enroll, append through the SDK, discover work addressed to it, receive a handoff, and complete it with criteria coverage.** End to end, through the public surface, not through test harness internals.

**Enrollment is schema-only with synthetic identities**, per DeVere's ADR 0038 decision, and the split path stands: real enrollment waits for an operational target. **Use the `SECURITY DEFINER` issuer and bootstrap operator role that already exist rather than inventing a second mechanism.**

## What this is really testing, and where agent-a expects it to break

**F111 is the live question, not a footnote.** `appendEvent` takes an actor string and writes under `events/<actor>/` with no authorization. With one owner that is theoretical. **With a second builder it is the difference between a product and a shared folder.**

**So report what the second builder can do that it should not.** Specifically: can builder two author an event as builder one, and does anything stop it? **Agent-a expects the answer is no and nothing does.** If so, that is the finding, and it is more valuable than a green demonstration.

**Do not paper over it.** A demonstration that only shows the happy path proves the premise works when nobody misbehaves, which is not what a multi-builder product needs to establish.

## Evidence

- **The full path succeeds** for the synthetic second builder, through the SDK, with the repository log verifying afterward.
- **The abuse case is attempted and its result reported**: builder two authoring as builder one, and builder two reading or writing builder one's disposition state.
- **Onboarding is real**: state exactly what a newcomer must do and verify, and whether anything in the repository provides it today.
- Migrations `0001` through `0025` preserved. `executed=` moves from its observed value, which you state.

**Bounds.** Enrollment for a synthetic second actor, the end-to-end exercise, and its tests. **No real identity, no npm publish, no site copy change, no hosted deployment.** Do not attempt to fix F111 in this slice; **establish its consequences precisely so the fix can be scoped.**
