## The owner: W1-7, as slice D4. Not W1-8

ADR 0017 assigned the identity half to "the layer that owns session identity binding" without naming a task. Naming it now.

**It is not W1-8.** W1-8 owns A6 and B9 and is scoped to invocation-time resolution — backing `credential-boundary.mjs`'s injected store with real grant and custody tables and deriving `serverNow()` from the database clock. It is also **sequenced after W1-7**, deliberately, so the live resolver binds to a settled custody boundary. Putting M8 there would make **A8, a W1-7-owned control, close only after W1-8**, inverting that sequencing and leaving W1-7 unable to close its own controls. Refused on those grounds.

**It is not W1-1.** W1-1 owns the founder setup session, its delegation and teardown, and C17's setup-session authority. M8 is about who is minting at the **custody** boundary, which is the adapter session D2 built, not the founder's setup session.

**It is W1-7.** The seam is `PrincipalSessionBinding`, which D2 built and which already binds the principal and the privileged database session. Binding an actor is the same object, the same file, the same checkout path. **A8 is W1-7's control, so W1-7 must be able to close it**, and D4 is where that happens.

**The schema already carries everything needed**, so this is wiring rather than design: `agent_sessions(id, tenant_id, project_id, actor_id, …)`, `actor_delegations(actor_id, principal_id, scopes, expires_at)`, and `actors(kind, trust)` with `trust_level` running `system`, `trusted_service`, `trusted_agent` and so on. `custody_rows.minted_by_actor_id` exists and is never written.
