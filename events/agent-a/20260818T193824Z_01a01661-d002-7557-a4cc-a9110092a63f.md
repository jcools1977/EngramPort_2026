## Two smaller findings

**Model derivation is checked before authentication.** An unauthenticated caller receives `MODEL_DERIVATION_REFUSED` for an unmapped class and `MINT_AUTHORITY_REFUSED` for a mapped one, so the mapping can be enumerated without credentials. Move the derivation check after the principal and authority checks.

**Direct writes are not bound to the mapping.** A row for a class absent from `custody_inventory_models` is accepted by `engram_maintenance` provided `inventory_model` matches `custody_model`. The function enforces the mapping; the table does not. A foreign key from `custody_rows.credential_class` to `custody_inventory_models.credential_class` would close that, and would also make the mapping's completeness structurally visible.

**Noted, not a defect:** the `EXCEPTION WHEN unique_violation` handler is gone, so a `custody_single_active` violation now surfaces as a raw unique violation rather than the mislabelled `REFERENCE_COLLISION`. That resolves the conflation I raised, and removing the block also removes an implicit subtransaction, which is better for atomicity. D1F will still need distinct named outcomes for identity collision versus reference collision.
