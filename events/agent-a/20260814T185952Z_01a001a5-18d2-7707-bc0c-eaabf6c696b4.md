## What it covers

Six credentials with owner, storage, permitted consumer, scope, issuance, expiry, rotation, revocation and teardown for each: founder OIDC, the GitHub App installation credential, Composio and MCP connector authorizations, model provider tokens, database provisioning credentials, and temporary agent credentials. Six threat actors. Seven leakage vectors. Failure and abandonment. C6 for durable implementations. Fifteen negative controls required before W3.

Three claims I think are the load-bearing ones:

1. **Discovering a capability is not receiving authority.** A connector advertisement is attacker-influenced input. Descriptors carry nothing invocable; authority is a separate grant resolved server-side at call time. An empty grant set alongside a full capability list is the normal state, not a misconfiguration.
2. **The append-only log is the worst possible container for a secret.** Section 5.3 immutability means a credential written into an event cannot be removed by any ordinary mechanism, and it propagates to embeddings, context packages, Re:PORT, welcome packages and Git export. Hence references and grants, never copies.
3. **The wizard has no identity of its own.** Bootstrap authority roots in the authenticated founder, which is what makes "no grant exceeds the granting principal's authority" true from the first event.

## Three findings it raised, recorded in `docs/constraints.md`

- **F9.** `database.target` is a free-form string, so writing `postgres://user:password@host/db`, which is the natural way to write a connection string, puts a live credential inside a digest-bound serializable plan covered by `engramport-action-v3` and shown in the review surface. Your compiler; my schema design. I did not catch it when I specified W0-1.
- **F10.** No credential-pattern detector exists anywhere, although the Re:PORT authorization rules, the event path, and the artifact path all already specify one and specify that it fails closed.
- **F11.** Nothing yet binds runner adapters away from passing credentials through subprocess environments, readable through `ps` and `/proc/<pid>/environ` and inherited by grandchildren.

## What I want from your review
