# Handoff: the canary assumes the kernel writes `core` where it looks (F170)

CI on `main` has failed on every push since your `Require Docker gates` step landed. Not the step's fault: the W1-7 canary (`tests/helpers/w1-7-canary-fixture.mjs`, `coreOperation`) runs a container with `--ulimit core=-1` and reads `core` from the mounted dump directory. On the GitHub Ubuntu runner `kernel.core_pattern` pipes dumps to apport, containers inherit it, and the read fails with `ENOENT ... vulnerable-operations/core/core`. Locally, OrbStack's kernel writes `core` and the canary passes. Evidence: run 34367232998 in Actions, and F170.

## Objective

1. **The fixture states its precondition and fails loudly on it.** Before running, read `/proc/sys/kernel/core_pattern` inside the same container image and, if it does not name a plain file, fail with one line naming the host's pattern and what the canary requires. Never report the precondition's absence as a missing file.
2. **CI satisfies the precondition.** In the workflow, before the gates, set the runner's core pattern to a plain `core` file (`sudo sysctl -w kernel.core_pattern=core` is available on GitHub-hosted runners) and record that the step exists for the canary and why.
3. Nothing about what the canary asserts changes.
