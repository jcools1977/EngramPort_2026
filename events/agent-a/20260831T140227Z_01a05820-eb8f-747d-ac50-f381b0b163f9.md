# Council 05 result

**Reported to DeVere for verification under ADR 0035.** The ADR 0041 sequence held: both digests were committed before either plaintext existed, and both reveals reproduce their digests exactly.

## Convergence

Both actors reject another in-tree attempt to make the log refuse impersonation. Both locate real prevention **outside the mutable log and before publication**, and distinguish that boundary from the log's integrity and audit role. Both read **F130 as evidence of a missing identity mapping at the hosting layer**, not proof that external controls are impossible. Both require the public claim to name its deployment assumptions rather than implying the repository alone supplies actor identity.

**That settles the architectural direction: stop adding identity rules beside the events, and design an admission boundary ordinary repository writers cannot rewrite or bypass.**

## Where agent-b corrected agent-a, and it changes the funding options

Agent-a recommended per-builder machines and hosting accounts, arguing the transport prevents builder B from pushing as builder A. **Agent-b's correction: that is writer authentication, and it is necessary but insufficient.**

**A host can prove which account pushed a commit while that commit legally contains an event whose `from:` names a different actor.** The relay deliberately permits one actor to commit another's events, which is why agent-a commits agent-c's. So authenticating the pusher does not authenticate the claim inside the file.

**This is the same distinction that killed step 4** (F131), arriving one layer up, and agent-a did not carry it across.

**The practical consequence is that Option C was never a closure path.** Per-actor path permissions on an Enterprise plan would prevent builder B writing *into builder A's directory*; they would not prevent builder B writing an event in its own directory claiming `from: agent-a`. Agent-a presented C to DeVere as a cheaper alternative to an admission service. **It is not an alternative; it is a weaker control against a different attack.**

## For DeVere

**Only an admission service that authenticates the caller and authorizes it for the claimed actor, before the write, closes F127.** Nothing cheaper does.

That strengthens rather than weakens the recommendation already given: **ship the free tier as structural integrity and auditability for cooperating builders, and build the admission service when a customer requires prevention and will pay for the infrastructure it needs.** The security boundary and the tier boundary are the same line.
