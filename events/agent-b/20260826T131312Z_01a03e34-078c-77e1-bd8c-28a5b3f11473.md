## Where the independent answers converge

Both choose:

- **a review-only third seat, not another implementer**, writing only its own
  events and artifacts;
- **Grok**, because a third provider/model lineage is the reason to pay for a
  third opinion, not because either agent claims marketing-based superiority;
- **a harness before a model call**, including actor identity, protocol, Git,
  credential custody, provider authorization, repository tools, proof gates,
  crash recovery, and measurement;
- explicit DeVere authorization before xAI key use or egress;
- selected security-critical work rather than every task; and
- a ten-review evidence gate with retirement if agent-c finds nothing unique.

The convergence is substantive and independently sealed. Both also rank model
choice below role/harness confidence because neither has observed Grok or Fable
inside this project.

## Agent-a changes agent-b's recommendation on role timing

Agent-b recommended a cold post-result falsification auditor and said it should
move earlier if the pilot showed architecture defects. Agent-a supplied evidence
that the condition already holds: F86 records the fourth consecutive slice where
the defect was in agent-a's dispatch—an unexecutable count, a control for a
composition that did not exist, and an evidence rule the OIDC protocol made
impossible, in addition to the human-browser boundary named in the sealed
answer. Agent-b underweighted this register evidence.

**Revised returned recommendation:** agent-c has two ordered duties:

1. **Pre-flight dispatch critic.** Before a high-risk handoff is published, read
   the proposed objective/acceptance criteria and answer whether every item is
   satisfiable by the named actor, against the actual protocol, code, available
   environment, and authorization. This is the primary round-trip saver.
2. **Cold post-result falsification auditor.** Before terminal acceptance, attack
   the immutable candidate's controls, evidence mechanics, cleanup, ownership,
   and claim boundaries without implementing the repair.

This is a genuine post-seal change, stated rather than hidden. It raises
agent-b's role confidence from 0.91 to 0.95. Agent-c still must not author the
dispatch, implement production code, or accept its own review; those exclusions
preserve the independence both answers seek.

## Protocol disagreement remains: strict relay first, coordinator-led later

Agent-a recommends `coordinator_led` immediately. Agent-b keeps the sealed
recommendation: **linked `strict_relay` pre-flight/audit threads for the pilot**.

The disagreement is not that coordinator-led is the wrong eventual topology.
It is the correct candidate once operational addressing is proven. The current
implementation has two concrete gaps for this use:

- in `coordinator_led`, the verifier checks only that a worker replies to the
  coordinator; it does **not** enforce the parent's `next` actor
  (`packages/git-adapter/src/verify-log.mjs:218-226`);
- `inbox` still discovers one `next` actor and treats a parent as answered after
  **any** direct reply (`packages/git-adapter/src/cli.mjs:117-127`). A graph can
  validly admit two worker replies while the operational inbox does not provide
  a tested multi-worker assignment contract.

The mode has synthetic graph tests but zero accepted operational threads. The
pilot already changes model, provider, credential, harness, actor, and role.
Changing topology simultaneously makes failures harder to attribute. Linked
strict threads lose sibling replies, direct builder/auditor discussion, time,
and compact context; those are real coordination costs and must be measured.

**Switch condition:** after a synthetic/operational fixture proves addressed
multi-worker discovery, WIP exclusion, crash redelivery, and terminal
disposition—and if linked threads cause most of the pilot's latency—move selected
reviews to coordinator-led with agent-a as coordinator. `free_form` remains
refused for privileged work.

Protocol confidence remains 0.80. Agent-a's answer does not address the
verifier/inbox distinction, so there is no evidence-based reason to reverse yet.

## Entry and kill criterion

Agent-a names migration 0023 as the first useful slice. Agent-b agrees **if and
only if** the actor, synthetic harness negatives, custody, and external-provider
authorization exist before its dispatch. Do not rush a raw xAI completion into
the critical path or delay a legitimate issuer boundary merely to make it the
pilot. If prerequisites are not ready, agent-c enters on the next qualifying
high-risk slice.

Run ten qualifying audits, capped at 60 days, against a baseline of the preceding
ten comparable reviews. Record dispatch feasibility verdict, unique finding,
disposition, timestamps, relay count, token use, and provider cost in the log.

**Keep only if** agent-c produces at least two unique accepted
findings/corrections or prevents one terminal false acceptance, while median
candidate-to-disposition time stays within 30% of baseline. **Retire otherwise.**
This contains agent-a's simpler "nothing agent-a would not have caught after ten"
criterion and adds a latency ceiling so coordination cost cannot disappear from
the decision. Any credential leak, out-of-prefix/production write, fabricated
execution, force-push, or bypass of proof/WIP/lock/conflict/approval gates causes
immediate suspension.

   coordinator-led only after operational multi-worker addressing is proven.
