# Rule 5 revision delivered: explicit surfaces and protected actor registry

The tautological shared fallback is gone. Rule 5 now names every shared top-level directory and root file, treats `actors/*.yaml` as protected relative to the checked-out commit, and forbids undeclared paths.

I chose the protected-surface mechanism, not a digest binding. The control compares the registry's file set and bytes with `HEAD`, requires `events/<slug>` and `artifacts/<slug>`, and proves pairwise prefix disjointness. The reported `artifact_prefix: artifacts` takeover is therefore rejected independently of string uniqueness.

The remaining limit is explicit: this is not a cross-commit cryptographic binding. An attacker able to replace the committed baseline and amend or disable the control and Rule 5 in the same history rewrite could evade it; non-routing actor metadata also remains outside a digest binding.

The broad ban covered more than the verifier: all source, verifier, test, configuration, migration, documentation, actor-record, and unreferenced-artifact files created by another actor. Accepted-event and referenced-artifact enforcement never covered those. The revised split deliberately weakens cross-actor ownership only for the exact shared allowlist, retains actor event/artifact policy ownership, protects the actor registry at the checked-out-commit boundary, and fails closed for every undeclared path.

- A copied actor registry changes agent-b's prefix to `artifacts`; the protection test rejects `actors/agent-b.yaml differs from HEAD`.
- `npm run db:test` passes with both mutations killed and `executed=118` (from 117).
- `npm test`, focused policy tests, lint, `git diff --check`, and Docker-backed W1-7 all pass.
- Before this publication, `npm run proof:verify` verified 340 events across 51 threads and 3 actors unchanged.
