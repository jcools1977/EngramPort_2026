This bounded D3 slice completes the section 10 canary harness with the remaining six sinks: operation logs, live process arguments, live process environment, core dumps, backups taken during the operation, and error message plus stack surfaces. It also tightens the accepted artifacts observer to require the vulnerable event file's exact `artifacts:` registration line as well as the dirty artifact bytes.

## Real landings and structural isolation

All ten vulnerable and protected twins use separate copied production module graphs, repositories, landing directories, observers, and a high-entropy synthetic canary. Only synthetic tenant `synthetic-canary-tenant`, key `synth-a`, local containers, and a known digest are used. Vulnerable importers never receive the Vault boundary, token, key name, or signing function; the live non-exportable signing boundary remains exclusively in the protected harness closure.

The six new vulnerable paths produced and independently observed these actual landing places:

| Sink | Vulnerable landing | Protected evidence |
|---|---|---|
| logs | operation-level JSON log containing the canary | trace-level log generated without the material |
| process arguments | worker snapshot of its live signing-operation `process.argv` | live argv contains no material argument |
| process environment | worker snapshot of the live signing-operation environment | live environment variable is absent |
| core dumps | forced SIGSEGV core generated by `pgvector/pgvector:pg16`; binary observer finds the held canary | safe process exits normally and creates no core |
| backups | file copied from the live operation store while the signing operation runs | backed-up store contains only synthetic-safe material |
| error surfaces | serialized exception message and stack both contain the canary | protected message/stack serialization contains no canary |

The platform host has core dumps disabled, so the fixture uses the repository's already-canonical PostgreSQL image with `--ulimit core=-1`, a bind-mounted task directory, and an in-container crash. The vulnerable command exits nonzero with `Segmentation fault (core dumped)` and produces a core whose bytes contain the canary. The protected twin exits without a dump. The task container and bind-mounted temporary tree are removed in `finally`; inability to generate or read the vulnerable core is a hard test failure, never a clean result.

For artifacts, the observer now reads the vulnerable event file and requires its `artifacts: [artifacts/agent-b/synthetic-canary-artifact.txt#sha256=...]` registration plus the matching dirty artifact bytes. It no longer credits an unregistered file alone.

Restoration returns `10/10` and exit 0. The no-op negative is separate: `baseline=0 applied=f after=0 restored=0`, exits 1, and is not included in `executed=18`.
