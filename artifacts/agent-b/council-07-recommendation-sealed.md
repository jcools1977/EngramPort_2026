I vote for a required environment object on each result in a new envelope version, carrying version, platform, tree_shape, and observed_at with explicit unknown values, for contested as a derived report condition rather than a result status, and for a new correction event type with a separate corrects link that cannot consume a relay turn.

## Concrete shape

Keep historical v0 and v1 events valid without rewriting or inferring their environments. Introduce this contract in a new schema version only after its append, inbox, and report controls are implemented together. This is a recommendation, not authorization to implement it in this council.

Each criteria_results entry has environment with four required members. version is an object containing source_revision (commit identifier or null), dirty (boolean or null), runtime (name and version or null), and subject (name and version or null). platform contains os, os_version, and architecture, each a string or null. tree_shape contains working_directory relative to the repository root and subject_root relative to that root, each a string or null; use a documented root marker, and prohibit absolute home paths. observed_at is an RFC 3339 timestamp or null. Null means unknown, never a wildcard match. Require an explanatory evidence reference for unknown fields; do not require the actor to invent facts merely to append a blocked result. Evidence already required by the result records the exact command, exit code, fixture/configuration identity, and relevant output. These four fields are a minimum comparison aid, not a complete reproducibility certificate. Do not put credentials or arbitrary environment-variable dumps into the object.

An environment belongs to one observation. Multiple runs in different environments must remain distinct observations; do not summarize a local pass and a remote failure into a single satisfied entry. Existing schema limits may require separate lawful events. This proposal does not grant a reviewer permission to append a second completion where the thread mode forbids it. A future design must choose an explicit result-bearing observation path before claiming general cross-actor conflict coverage.

Retain satisfied, unmet, and blocked. A completed reproduction that does not demonstrate the criterion is unmet relative to that criterion; an unavailable prerequisite is blocked. Could not reproduce is not automatically blocked. Owner acceptance is a separate decision, never a fabricated satisfied result.

Derive disagreement using the issuing handoff id and criterion id together. Reused criterion ids in different handoffs must never collide. Among active, unsuperseded observations for that criterion, differing statuses produce an unresolved disagreement group. The report labels satisfied versus unmet as contested and includes both environments. If one side is blocked, label the group blocked-versus-observed rather than implying an empirical contradiction. Incompatible environments produce environment-divergent contested observations, not proof that either run is false. Unknown environments remain incomparable. These are report labels, not additions to the result status vocabulary.

No last-writer-wins resolution. Resolution references the particular prior observations and replacement evidence. Reproduction across both pinned environments can resolve a factual difference; narrowing the owner's requirement creates a new criterion revision and leaves the original disagreement visible as scope changed. It must not retroactively transform the prior failure into a success. No automatic clearance from matching timestamps, actor agreement in prose, or an owner decision about acceptability.

For correction, introduce type correction with corrects naming an existing same-thread event from the same actor, in_reply_to null, and next null. Explicitly define this as a non-root annotation despite the null causal parent, and require the corrects target to precede it. Root counting and causal validation must recognize this distinction. Corrections are outside relay successor accounting and do not become inbox work. Reject artifacts/results/criteria replacement in the correction envelope; its body identifies the exact original passage and corrected statement, with supporting artifacts where appropriate. Render the original and annotation together. A correction can qualify or retract a narrative claim, but cannot change an accepted status, recipient, criteria, evidence digest, or original event bytes. A structured result needs a new lawful result and explicit supersession semantics, not a prose correction that silently edits the report.

This intentionally leaves correction as a narrow first step. Repeated annotations all remain visible in append order and do not silently overwrite each other. Corrections cannot target correction events initially. A report must flag inconsistent annotations for human review rather than invent a precedence rule.

## Strongest case against

This adds schema burden while leaving the most consequential environmental variables in evidence. Two runs can report identical source revision, runtime, OS, tree paths, and clean trees yet contact different database schemas through the same service URL. One passes and one fails. A reader who treats the structured object as a complete environment fingerprint will infer nondeterminism or dishonesty when the hidden database state explains both results. Unknown-filled objects can also become bureaucratic boilerplate. Required fields improve the visibility of missing knowledge; they do not prove the knowledge exists.

The correction design is a second edge relation and therefore expands every graph consumer's obligations. A client that still assumes every null in_reply_to is a root can reject a valid annotation. A report that hides the corrected sentence can make an author appear never to have claimed it. Worse, an operator could read a narrative retraction as overturning an accepted satisfied status. If consumers cannot show both the unchanged status and the retraction warning, defer correction deployment instead of accepting this ambiguity.

A narrower optional environment extension is cheaper. I reject it for newly versioned results because silently absent metadata would remain indistinguishable from forgotten collection. Compatibility is handled through versioning and explicit unknowns, not through invented historical metadata.

## Controls that would show failure

These are proposed discriminating controls, not executed tests or existing capabilities. Reachability refers to the public path a future implementation must exercise.

1. Environment omission and malformed timestamp: append a new-version result without environment, then with an invalid observed_at. Append must refuse both, accept an explicit unknown with evidence, and continue accepting valid historical envelopes. Reachable through append; report must preserve unknown rather than infer a platform.
2. Tree-shape discrimination: record the same command with repository-root and nested subject-root layouts and opposite observations. Report must retain both paths and statuses under one criterion. Reachable through append to record and report to observe. Swapping a path to unknown must prevent a claim of environment equivalence.
3. Criterion isolation: reuse a criterion id under two different handoffs with opposite statuses. Report must not mark them contested against each other. Reachable through append and report.
4. Status discrimination: compare satisfied/unmet with satisfied/blocked for the same criterion. Report must show a factual contest for the former and a missing-prerequisite distinction for the latter. Reachable through append and report. No owner decision may silently turn either into satisfied.
5. False resolution: append a later pass in only one of two conflicting environments. Report must keep the other unresolved observation visible. Reachable through append and report. A control that merely checks for a contested label's presence is insufficient; this mutation must fail any premature clearance logic.
6. Correction ownership: attempt to correct another actor's event, an unknown target, and a correction event. Append must reject each; a same-actor narrative correction must succeed. Reachable through append. Verify the accepted target remains byte-identical.
7. Turn conservation: create an addressed review, append its author's correction, then query the recipient inbox. The original review must remain present and its recipient must still be able to make the normal reply. The correction must not itself appear as new work. Reachable through append and inbox. Repeat with an already answered review and confirm the correction does not reopen it.
8. Historical fidelity: report a correction beside the original passage and accepted status. Removing the original or presenting a changed status must fail. Reachable through report after append. A correction that merely says a result was wrong must surface a warning without becoming a replacement result.
9. Mode and ordering coverage: perform turn conservation in strict_relay, free_form, and coordinator_led, with mode-specific annotation permission defined explicitly as author-only and not a coordinator turn. Append must reject ordinary self-replies still forbidden by the mode. Reachable through append, inbox, and report. Annotation must not become a generic bypass of normal event permissions.

## Reversibility

Environment can be retired for future versions while old schemas and hashes remain readable. Existing values remain historical claims. Retiring it costs version negotiation, SDK migration, fixtures, and report support; deleting old fields would invalidate accepted evidence. Derived contested labels are easier to revise, but reports must pin the derivation version so changed classification is not confused with changed observations.

Correction is more expensive to retire because a second graph relation becomes permanent historical data. Stop new correction appends through a versioned policy, retain readers and inbox exclusion for accepted annotations, and preserve their original targets. Removing that exclusion could resurrect or consume turns incorrectly. This long-lived graph cost is the strongest reason to keep correction narrow and to require all three public paths before adoption.

## Failure class covered and not covered

Covered beyond today's directory-layout incident: the same criterion passes on one runtime version and fails on another; the environment makes those observations distinguishable. Also covered: an author discovers a mistaken command or sentence in an addressed review and needs to annotate it while the recipient still owns the open response.

Not covered: maliciously falsified environment fields, hidden mutable service state, proof of execution, authenticity of a human approval, or disagreements about whether a product is acceptable. The owner can record an acceptance decision, but the protocol cannot derive agreement from that authority. Nor does a correction cancel an external action already taken because of the original claim.
